## 完整牌局

四个真实 WebSocket 客户端使用服务器提供的 `legal_actions`，在服务器内注入 Seed 20260916（没有公开给客户端），共执行 **94 次经过身份验证的动作**，从掷骰走到自然流局，然后由房主开始下一局，由连庄庄家重新掷骰、完成发牌。

这段验证没有从网络暴露任何调试 fixture 路由，没有直接推进牌局到流局。罕见的吃碰胡并发、杠和抢补杠测试使用原有服务端 fixture 构造场景；之后的所有玩家动作均通过 WebSocket 执行。

## 实际入口及前端脚本联调

实际启动独立进程：`python web_server.py --host 0.0.0.0 --no-browser --port 8765`，健康接口返回 `version: 0.4.0`。

四个独立 jsdom 客户端加载服务器提供的真实 `lan.html`、`presentation.js`、`app.js`、`lan.js`，通过真实 HTTP/WebSocket 连接完成：

- 点击创建/加入、东南西北入座、房主开始、庄家掷骰。
- 发牌后只有本人区域出现可操作牌面，另外三家全部牌背；四边共 136 个牌墙层元素。
- 模拟关闭并重新加载西家页面，恢复原身份、原手牌、原座位；其他玩家看到离线/上线。
- 连续 16 次通过页面按钮提交操作，四个 DOM 的 revision 一致，持续检查私有手牌与牌墙。
- 昵称 HTML 正确转义。
- 单机 `/local.html` 掷骰后显示 53 张可见手牌，仍可由一个人操作四家。
- 全流程无 JavaScript 执行错误。

`node --check` 对 `web/app.js`、`web/lan.js`、`web/presentation.js`、`tests/ui_smoke.cjs` 均通过。Python 源码编译检查通过。

## 核心兼容性检查

逐文件比对原压缩包，`mahjong/` 下只有 `game/engine.py` 改动：表现层事件增加观看者参数，并对其他玩家隐藏暗杠牌型。麻将求解、动作执行、响应裁决、牌墙与庄家规则没有改写。原 `web/presentation.js` 与 v0.3.1 逐字节一致，五类表现层接口均保留。

## 实测范围限制

当前远程浏览器访问本地服务器时返回 `ERR_BLOCKED_BY_CLIENT`，所以**没有完成真实 Chrome/手机的截图、触屏或视觉排版验收**。上述前端联调是 jsdom 的 DOM/脚本验证，不是浏览器渲染截图验证。

Windows `.bat` 脚本已按 Windows 命令语法、UTF-8/CRLF 编写并检查，但本次环境是 Linux，未在实体 Windows 系统上双击运行。也未使用真实 Wi-Fi 手机做硬件联机验收。

本版保留原计分配置待确认状态，无账号、云存档、托管或公网加密部署。服务器重启会清空临时房间。
