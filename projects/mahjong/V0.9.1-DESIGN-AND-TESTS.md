# 青雀麻将 v0.9.1 · 正方形牌桌与四向牌河

**基线**：用户提供的 v0.9.0「春樱牌桌」完整ZIP。所有更改均在本地完成；未修改 GitHub 仓库。

## 设计问题与修改

v0.9.0 的2D桌面仍是长方形，南家手牌在桌面外的独立面板中，左右牌河的独立百分比布局易产生重叠，金牌信息漂浮在中央牌旁。

v0.9.1 将牌桌、场景与手牌归入统一的正方形坐标系统：

- **正方形桌面**：桌面宽高始终相等；桌面尺寸由实际视口与可用空间限制。PC留出两侧控制栏，手机横屏使用左右空白区，手机竖屏将操作按钮移至桌面下方。
- **自家手牌回桌**：将现有可点击、选牌、双击出牌的 `article.player.dock-seat` 作为透明定位覆盖层，真实手牌排列在牌桌内部最下方；没有复制手牌，不改变DOM事件处理或后端行动协议。头像、托管、牌况、十三幺拾牌和动作按钮保留在桌外的操作位，不占独立手牌面板。
- **对称牌河**：四家复用相同的7列格网，以180°/90°/-90°旋转显示；弃牌较多时依次切换为8列、10列，缩小单张牌的尺寸并向外调整边缘，避免向中央挤压。金牌/副露/上金/拾牌/报听公开牌仍在各自区域。
- **中央金牌**：金牌及标记放到中央计分牌右下角，风位、局数、剩余牌数及骰子仍保留；不再有独立的金牌浮框。
- **视角按钮**：沿用v0.9.0原有操作入口，保留 `overhead-view` 切换，但在正方形布局下不再拉伸桌面。

`web/v091.css` 是新的完整几何层，加载于 `v09.css` 之后。2D渲染仍由 `web/table-scene.js` 完成；已删除对独立金牌浮层的依赖。未使用整张游戏截图作界面素材。

## 浏览器与自动化验证

- 使用 Chromium 以 **1440×900、1024×768、820×1180、390×844、844×390** 五种视口渲染本地静态原型。检查结果：牌桌计算宽高比都为 **1.000**；不发生页面横向溢出；页面无 JavaScript 异常；麻将牌SVG全部正常解码。
- **牌河压力测试**：在1440×900、390×844、844×390分别模拟每家**20、30、40**张弃牌（共9组，40张/家属于远超正常牌局的压力输入），使用DOM包围矩形检查四条牌河与中央计分牌。修正拥挤模式失去定位的问题后，9组均无交叠。
- **真实状态/交互**：从本地Python服务生成真实掷骰后的游戏状态，注入浏览器；界面显示14张可操作手牌。Chromium实际点击选牌、再次点击同牌，前端发出 `DISCARD` 请求，包含正确 `seat`、`round_id`、`revision`、`tile_ids`；模拟请求回包来自服务端执行后的真实状态，并显示新增弃牌。三种主要视口均无 JS 异常。
- **Python回归**：`python -m unittest discover -q`——共 **179项，全部通过**（含新增7项v0.9.1布局回归）。
- **JavaScript**：使用 `node --check` 检查主要的浏览器脚本。
- **CSS**：Chromium成功解析样式；使用CSS解析器检查新几何文件。

**测试限制**：本执行环境的Chromium阻止本地URL和本地文件导航，因此浏览器验收采用**相同HTML/CSS/JS源码与静态资源临时内嵌到 `page.set_content` 的方式**，而非对 `http://127.0.0.1` 的直接端到端浏览。真实服务API由Python本地请求调用，并用于前端交互回包；没有在原生Windows机器上验证 `.bat` 启动，也没有独立验证真实WebSocket多设备联机UI。规则引擎及现有LAN测试仍纳入自动化回归。

## 运行

完整解压后双击 `启动网页版.bat`（单机）或 `启动局域网联机.bat`（联机），首次需要 Python 3.11+ 及依赖安装。`/prototype-v091.html` 可在游戏本地服务器启动后独立浏览静态原型。
