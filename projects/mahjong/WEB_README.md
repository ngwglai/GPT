# Web 版使用说明 · v0.5.0

联机启动、加入房间、身份恢复及测试方式，以项目根目录 `README.md` 为准。十三幺拾牌见 `THIRTEEN_ORPHANS_V0.5.0.md`。

- `start_lan.bat`：同一局域网四人联机，自动准备依赖。
- `start_web.bat`：仅本机可访问的启动方式。
- 首页 `/`：选择模式；`/local.html`：原有四家明牌测试；`/lan.html`：联机房间。
- 原有素材管理、三路音量、动画、提示和事件总线继续使用 `web/presentation.js`。
- 素材仍放在 `web/assets/`，映射仍是 `web/assets/manifest.json`。

当前 Web 服务器用 Python 3.11+ 和 `requirements.txt`。以下也收录了旧版加入的功能。

# 四家明牌 Web 测试版

这是给规则调试用的本地网页，不是联网成品。一个浏览器页面同时显示东、南、西、北四家的完整手牌，由同一个人操作四家。

## 最简单的启动方式（Windows）

1. 解压整个压缩包。
2. 双击 `启动网页版.bat`。
3. 正常情况下会自动打开浏览器；如果没有自动打开，访问 `http://127.0.0.1:8765/`。
4. 命令窗口不要关，关掉就等于停止本地服务器。

也可以在项目目录运行：

```bash
python -m pip install -r requirements.txt
python web_server.py
```

## 页面操作

- 北家在上、南家在下、东家在左、西家在右。
- 四家普通手牌全部明牌，仅用于单机测试规则。报听牌会单独显示在玩家区域的“报听牌”位置。
- 可操作的手牌会有悬停效果。先点牌，再点该玩家区域下方出现的 `打出 / 报听并打出 / 上金 / 暗杠` 等按钮。
- `胡 / 过 / 吃 / 碰 / 杠 / 拾幺牌` 会直接出现在符合资格的玩家操作区。拾来的牌会显示在独立的十三幺拾牌区。
- 遇到多人响应时可以逐家操作；也可以点顶部的 `未响应者全部过`。
- 对局进行中时，主按钮显示 `重新开局`，会按顶部当前的种子/庄家重新开始，适合调试。
- 本局结束后，主按钮自动变为 `下一局`：庄家胡牌或流局时连庄；其他玩家胡牌时庄家按东→南→西→北顺延一位。下一局会自动生成新的随机种子。
- `按设置重置整场` 会清空连续牌局的局数、上一局结果和累计计分预留状态，并使用顶部指定的庄家/种子重新从第 1 局开始。
- 页面中央会显示当前是第几局、本局 Seed、上一局结果以及计分状态。

## 前后端边界

规则仍由 Python `GameEngine / TableService` 决定。浏览器不计算胡牌、听牌、吃碰杠、金或响应优先级。

为了实现“四家明牌测试模式”，本地 Web 服务分别取得四个玩家各自的 `player_view`，再合并给同一个测试页面。它没有把 `GameState`、随机墙序、墙内隐藏牌型/实体 ID 或原始 `event_log` 暴露给前端；0.3.1 仅新增不含牌面的公开牌墙几何状态。

金规则按本次确认版本：金不能普通弃入牌河，只能保留或上金；首次上金前不能胡；上金相当于出牌，不补牌、不进入弃牌响应窗口，直接轮到下家。


## 报听牌规则（0.2.1）

- 宣告听牌时选择的那张牌不会进入普通牌河，而是保存为该玩家的 `ting_tile`。
- 这张牌不产生吃、碰、杠、胡响应，报听完成后直接轮到下家摸牌。
- `ting_tile` 已经离开结构手牌，不参与之后的胡牌和听口计算，但仍计入 136 张实体牌守恒。
- 正式 `player_view` 中，本人能看到真实报听牌；其他玩家只能知道“这里有一张暗牌”，收不到牌型和实体 ID。
- 本地四家明牌测试页是把四个玩家各自的本人视图拼在一起，因此页面上会显示每家自己的报听牌正面；这不代表正式对手视图会泄露。


## 连续牌局（0.3.0）

Web 层现在只保存少量跨局状态：局数、当前/上一局 Seed、上一局结果、庄家以及计分累计槽。单局麻将状态仍全部由 `GameEngine` 管理。

庄家切换直接采用核心规则层已有的 `RoundResult.next_dealer`：

- 庄家胡牌：连庄。
- 流局：连庄。
- 任意闲家胡牌：当前庄家顺延一位；并不是“谁胡谁坐庄”。

每次正常点击 `下一局` 都会生成新的 64 位随机 Seed，并把上一局的 Seed 和结果记入本地连续牌局历史，方便发现问题时复现。

## 计分

Web 默认使用 v0.4.0 的计分配置。只有某局 `Settlement.status == CALCULATED` 时才会累计实际转移。缺少结算规则的情况会显示“计分：待配置”。

## 掷骰、实体牌墙与表现层（0.3.1）

Web 新局现在先进入 `ROLLING_DICE`，四家都尚未发牌，只有庄家会得到 `ROLL_DICE` 合法操作。庄家点击“掷骰子”后，服务器公开由本局 Seed 确定的两个骰子结果、开牌位置和金指示牌，然后才完成初始发牌并进入正常出牌阶段。

骰子结果仍然由服务器控制，前端不随机。因此同一个 Seed、同一个庄家可以重复得到相同骰子、相同开牌位置、相同金和相同初始手牌，继续适合规则调试。

页面中央增加四面实体牌墙。每面 17 墩、每墩上下两张，共 136 张。`wall_view` 只公开物理位置是否仍有牌、保留区、开牌墩、正常摸牌端和杠后补牌端；不会返回墙内任何未摸牌的牌型或实体 ID。发牌、普通摸牌和杠后补牌都会直接反映在牌墙上。

前端增加独立表现层 `web/presentation.js`：

- `AssetManager`：麻将牌、牌背、桌面、UI、骰子、音频和特效资源映射。
- `AudioManager`：BGM / SFX / Voice 三路独立控制。
- `AnimationManager`：吃碰杠胡、摸打牌等视觉反馈接口。
- `NotificationManager`：轮到玩家、吃碰杠胡等短提示。
- `PresentationEventBus`：消费服务器提供的安全 `presentation_events`，把游戏事件分发给声音、动画与提示。

资源位于 `web/assets/`，映射入口是 `web/assets/manifest.json`。默认使用 CSS 文字牌面，包内附带 BGM 和语音。
