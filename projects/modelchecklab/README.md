# ModelCheckLab v0.1

面向学习者和开发者的显式有限状态模型检验器。在本地浏览器中，用真正的广度优先搜索（BFS）枚举模型的可达状态，检查不变量、非终止死锁和目标可达性，并重建最短反例。计算在 Web Worker 中执行；核心算法不依赖 React 或 DOM。

无需服务器后端、数据库、账号或付费 API；不上传模型，不执行用户 JavaScript，不部署外部站点。开发/预览只启动本机静态 HTTP 服务。

## Windows / Linux 启动

需要 Node.js 22.12+（建议 22 LTS）及 npm。安装依赖时需要网络，之后页面运行不请求外部服务。

Windows PowerShell / cmd：

```sh
cd projects/modelchecklab
npm ci
npm run dev
```

Linux Bash 使用相同命令。浏览器打开终端显示的 `http://127.0.0.1:5173`；端口占用时以 Vite 实际输出为准。停止服务按 Ctrl+C。Windows PowerShell 若限制 `npm.ps1`，使用 `npm.cmd ci`、`npm.cmd run dev`。

运行生产构建：

```sh
npm run build
npm run preview -- --port 4182 --strictPort
```

打开 `http://127.0.0.1:4182`。需要通过 HTTP 访问，直接双击 `dist/index.html` 的 `file://` 方式不支持 Worker 加载。各项目独立安装和启动，不依赖仓库其他项目。

## 使用

1. 选择八个内置模型之一，或导入/编辑 JSON；点击“校验模型”查看中文结构和类型反馈。
2. 设置预算，点击“运行检验”。可取消或重置，计算期间仍能切换主题。
3. 分别查看安全结论和目标可达性；反例可单步、拖动进度、自动回放，变化变量突出显示。
4. 展开小规模状态图，悬停查看状态和动作。导出模型、完整检验结果或反例轨迹 JSON。

修改模型会清除旧结果。运行期间锁定模型与预算；重置会终止 Worker 并保留编辑文本。导出结果携带本次模型及预算，可重新导入其中的 `result.model` 复现；耗时、超时和取消点随设备变化，正常探索及反例顺序确定。结果包不是模型文件，请取出模型字段后导入。

## JSON 模型

顶层七个字段均必需，拒绝多余字段。下列模型有 3 个可达状态，正常终止于 `x=2`。

```json
{
  "name": "有界计数器",
  "variables": { "x": { "type": "int", "min": 0, "max": 2 } },
  "initial": [{ "x": 0 }],
  "actions": [{
    "name": "递增",
    "guard": { "op": "<", "args": [{ "var": "x" }, 2] },
    "set": { "x": { "op": "+", "args": [{ "var": "x" }, 1] } }
  }],
  "invariants": [{
    "name": "保持非负",
    "expr": { "op": ">=", "args": [{ "var": "x" }, 0] }
  }],
  "terminal": { "op": "==", "args": [{ "var": "x" }, 2] },
  "goals": [{ "name": "到达2", "expr": { "op": "==", "args": [{ "var": "x" }, 2] } }]
}
```

变量域：

| 定义 | 含义 |
| --- | --- |
| `{"type":"int","min":0,"max":3}` | 包含两端点的有限安全整数 |
| `{"type":"bool"}` | `true` / `false` |
| `{"type":"enum","values":["idle","busy"]}` | 非空、无重复的有限字符串集合 |

变量名以英文字母开头，后续仅字母/数字/下划线，最多 32 字符，拒绝保留原型键；显示名称支持中文，最长 80 字符。初始状态为非空数组，每项必须恰好包含全部变量且在域内。允许多个初态，重复初态去重。

表达式是整数/布尔/字符串字面量、`{"var":"变量名"}` 或 `{"op":"运算符","args":[表达式,...]}`。不支持属性访问、函数、循环、字符串脚本、`eval` 或动态代码。

| 运算符 | 参数与结果 |
| --- | --- |
| `+`、`-`、`*` | 两个整数 → 安全整数；中间结果溢出即错误 |
| `<`、`<=`、`>`、`>=` | 两个整数 → 布尔 |
| `==`、`!=` | 两个相同类型值 → 严格比较的布尔值 |
| `and`、`or` | 2–16 个布尔参数 → 布尔，所有参数均求值 |
| `not` | 一个布尔参数 → 布尔 |

动作名称唯一，守卫为布尔表达式，`set` 至少赋值一个已定义变量。每个动作给出一个确定性后继；多个启用动作用于表达非确定选择，有限选择可展开为多个动作。所有赋值读取同一个**更新前状态**，未赋值变量保持原值，整个更新原子完成。例如 `a=b; b=a` 交换旧值。禁用动作不执行其赋值。

`invariants` 和 `goals` 各为名称唯一的 `{name,expr}` 数组，可为空；`terminal` 为布尔表达式。合法终止状态仍检查不变量/目标，然后停止扩展，即使其守卫为真也不执行动作。非终止状态若无启用的合法动作就是死锁；自循环是合法后继，不属于死锁。不支持公平性或“最终一定终止”等活性性质。

## 检验结果语义

| `status` | 准确含义 |
| --- | --- |
| `verified` | 完整探索完成，给定有限模型的指定不变量及非终止死锁检查未发现违反 |
| `counterexample` | 在真实可达状态发现不变量违反、非终止死锁或定义明确的语义错误 |
| `inconclusive` | 状态/转移/时间/输入结构资源超限、取消、Worker 故障等，无法完成验证 |
| `invalid_model` | JSON、字段、域、初态或表达式类型等静态定义不合法 |

`verified` 不能证明实际程序绝对正确；结论受模型抽象、有限域和所指定性质约束。缺少不变量时，仍检查非终止死锁与运行时语义错误。

目标单独标记 `reachable`（已发现真实见证）、`unreachable`（只有完整探索才能确定）、`unknown`（尚未找到且探索未完成）。发现一个反例后即停止，尚未检查的目标保留 unknown，即使它们在其他路径上可能可达。已发现的目标在后续预算耗尽时仍保持 reachable。可达目标见证超过 1,000 个状态时，导出用 `witnessOmitted: true` 明确省略该可选路径；不会改变真实可达结论，反例路径不截断。

反例类别：`invariant`、`deadlock`、`action_error`（启用动作越界、枚举域外更新或更新算术溢出）、`evaluation_error`（守卫/性质等表达式计算溢出）。错误不是死锁或合法终止，也不是悄悄忽略的转移。非法初态是 invalid_model。动作更新错误的轨迹停在合法前置状态，`violation.action` 标明失败动作，不伪造非法后继。

BFS 保留每个新状态的首个前驱。状态按变量名排序的值数组 JSON 序列化去重；动作按名称的 JavaScript 字符串顺序遍历，初态按输入顺序入队。同深度并列结果按此顺序选择。反例按其违反/失败前置状态的最少合法转移数重建；初态违反长度为零。不会声称给出全部反例。

统计：`states` 为已发现的不同合法状态数，`transitions` 为已生成的合法动作边数（包括重复目标/自循环），`expanded` 为完整处理的状态数。导致停止的错误赋值不算合法转移；状态预算耗尽时已计算的最后一条边可计入 transitions，但新状态未入队。`complete` 明示探索是否完整。

## 四组案例

| 案例 | 正确版本 | 错误版本及预期反例 |
| --- | --- | --- |
| 双进程互斥 | 原子检查并获取布尔锁 | 忽略锁，2 步后两个进程同时处于临界区 |
| 双锁死锁 | 两个进程按同一顺序获取双锁，完成后释放 | 相反顺序获取，各持一锁，2 步死锁 |
| 银行余额守恒 | 同一个原子动作扣款并入账 | 扣款漏记入账，1 步违反总额守恒 |
| 有界生产者消费者 | 容量 2，生产/消费各 3 次，检查库存守恒 | 消费不减库存，2 步违反守恒 |

所有案例仅是普通模型数据，使用和用户输入完全相同的校验器与 BFS，不按名称判断结果。正确案例的目标均可达。

## 资源与实现边界

硬预算为 50,000 个状态、200,000 条合法转移、15,000 ms，界面允许降低预算。输入/导入最多 64 KiB（UTF-8），最多 12 个变量、1,024 个初态、128 个动作、每类 32 个性质、枚举 64 个值、AST 深度 24、单运算最多 16 个参数。资源超限返回 inconclusive。图最多 500 节点和 2,000 边，超出显示截断提示；图的截断与检验是否完整无关。

Worker 每 64 个处理状态让出事件循环以接收取消，在状态和动作间检查时间；极端单次表达式计算并非可抢占。主线程另有响应超时保护及取消兜底，强制结束时明确返回 inconclusive，部分目标/图可能不可用。预算不是精确内存配额；复杂模型可能先受浏览器内存约束。有限域较大也会产生状态爆炸。

内核目录 `src/core/`：`types`（协议）、`validation`（严格模式/类型）、`state`（规范化）、`expression`（安全解释器）、`transition`（原子更新）、`properties`（性质）、`search`（BFS/预算）、`trace`（前驱重建）。`check.worker.ts` 只适配消息，React 只负责输入与展示。

## 测试与 CI

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit --audit-level=moderate
```

Linux 若缺少浏览器系统库，用 `npx playwright install --with-deps chromium`。可用 `CHROMIUM_PATH` 指定已有 Chromium；Windows PowerShell 使用 `$env:CHROMIUM_PATH='C:\path\to\chrome.exe'`。

单元覆盖枚举、循环/去重、多初态、最短反例、原子更新、终止/死锁、目标三态、非法模型、取消、真实默认预算及八个案例。独立参考测试以 **100 个固定种子**生成有限图，DFS 求可达集合、边松弛求距离，比较模型内核的状态集合、边数、所有目标、错误检测和真实最短路径，不复用表达式或转移实现。每个种子分别检查完整模型、不变量错误、死锁和域外动作。

Playwright 对生产构建执行真实 Worker 流程及 JSON 导入导出/回放/主题/窄屏/异常测试。根 CI 调用独立 `modelchecklab.yml`，Linux/Windows 原生 Runner 安装锁定依赖、审计、lint、类型、单元、构建和 Chromium E2E，汇总到 `CI required`。隐私检查依仓库 AGENTS.md 及根脚本执行。实际执行证据与未验证事项见 [VALIDATION.md](VALIDATION.md)。

## 与 TLA+ / TLC 的关系

本项目借用显式有限状态枚举、不变量与反例轨迹的思想，适合教学和小型状态机实验。它不是 TLA+ 语言实现，不读取 `.tla` / `.cfg`，不调用 TLC，也不能替代 TLA+ 工具链。v0.1 没有时序逻辑、公平性、活性、对称约简、偏序约简、分布式搜索或符号模型检验。模型必须直接给出有限变量域与原子动作。

后续可在独立正确性测试基础上扩展参数化动作、状态空间约简和更丰富的图布局；活性检查需要明确循环与公平性语义后另行设计。Firefox/WebKit、真实移动设备和用户电脑人工试用不视为本次已验证范围。
