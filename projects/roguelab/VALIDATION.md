## 已在开发环境实际执行

- Godot 4.6.3 stable：编辑器无头导入、全部 GDScript 编译、主场景启动。
- `test_run.gd`：**543 项检查，0 失败**。包含三职业开局、确定性地图/抽牌、非法操作原子性、能量/护盾/毒素/虚弱/易伤/充能/升级、药剂、牌堆、商店/事件/奖励/死亡/三幕推进与通关、存档损坏拒绝与随机状态重放、每张卡牌结算、100 个地图种子。
- `test_ui.gd`：首页、地图、战斗、奖励、休息、商店、事件、胜负结算和七种弹层全部创建并处理帧，无 GDScript 错误。
- `simulate.gd`：固定种子 0–19 × 三职业，真实执行选择、出牌、路线、奖励与资源消耗；**60 局全部终止，无卡死**。Threat 0：57 胜 / 3 负（Warden 20、Mycologist 20、Engineer 17 胜）。Threat 4：30 胜 / 30 负（13、16、1 胜）。这是一种启发式自动策略的抽样，不是玩家胜率或完备平衡证明；Engineer 在最高难度下对策略要求明显更高，仍需玩家反馈。
- Godot 官方模板 SHA-256 核验后，Web 单线程与 Windows x86_64 release 导出成功。
- Chromium / Playwright 1.62：**9 项浏览器检查通过，零浏览器错误**。实际点击开局、输入种子、战斗出牌到奖励、选卡、刷新并继续、取消替换存档、960×600 缩放；读取正常 IndexedDB 保存的数据核对进度与 RNG。测试不注入游戏接口、不修改保存数据。
- 仓库隐私防护回归：**53 项测试通过**。开发初始化确认匿名 noreply 身份、安装现有 hooks，迁移审定旧误列项时保留私有备份。既有 127 个可达提交、675 个唯一 blob 检查通过，私人词表已加载。

## CI 与发布门槛

RogueLab 独立 workflow 在 Linux 重复规则、UI、整局模拟、Web 操作和两平台导出；Windows runner 运行原生规则/UI/整局测试，并实际启动生成的 Windows EXE，检查退出码及成功标记。仓库原有 CI 保持不变，其 required 检查与隐私规则仍适用。合并前检查远端任务结果；不以本地交叉编译冒充 Windows 已运行。

Release 仅在 main 且 Linux / Windows 都成功后创建，发布 ZIP 和 SHA-256 校验表，不替换已有版本。Pages 单一聚合工作流重新构建并验证 EntropyLab 与 RogueLab，再发布两个子路径；推送只构建，发布需要 workflow_dispatch。最终 PR、运行和发布结果可由 GitHub 工作流记录验证。

## 已修复的验证发现

- JSON 将整数读成浮点后，存档集合验证会拒绝正常数据：先规范化合法整数，再做完整结构验证，覆盖精确 RNG 重放。
- 初始地图安全节点过多：第 3、5 层改为战斗/精英选择，提高资源消耗与构筑检验，强化首领生命。
- 默认字体缺少部分符号：交互提示改为可渲染字符；修正卡牌说明宽度及生命条视觉尺寸。
- 卡组堆查看不应暴露未来抽牌顺序：显示排序后的抽牌列表；弃牌与消耗数量仍可查看。
- 键盘战斗命令在输入阶段消费，避免焦点按钮误吞空格/方向键。

## 未验证及限制

未声称真人长期平衡测试、Windows 图形窗口人工试玩、Safari/Firefox 实机验收或完整移动端适配。自动策略对三职业的优化程度不同。游戏是完整单人 v1，不含联网排名、云同步、中文界面与屏幕阅读器语义支持。测试截图和构建产物不进入源码提交，也不随游戏 PCK 打包。
