# DeltaLab — Incremental Computation Laboratory

DeltaLab 是完全在浏览器本地运行的增量计算实验室。面向学习者与算法实验者，在可编辑的计算 DAG 上比较完整重算、脏节点传播和输出变化传播的实际运算次数。不是用动画推测结果：核心先真实执行并记录 trace，界面再逐步回放；所有结果由独立完整重算路径逐节点验证。

不需要后端、账号、密钥或付费服务。构建后的页面不访问外部资源；首次安装依赖和浏览器需要联网。与仓库其他项目独立，不部署网站。

## 安装与启动（Windows / Linux）

需要 Node.js **22.12+**（建议 Node.js 22 LTS）及 npm。在 PowerShell、Windows Terminal 或终端执行：

```sh
cd projects/deltalab
npm ci
npm run dev
```

访问终端显示的本地地址（通常为 `http://127.0.0.1:5173`）。Windows 同样使用上述命令；若 PowerShell 执行策略阻止 `npm.ps1`，使用 `npm.cmd ci` 和 `npm.cmd run dev`，无需降低系统策略。

生产运行：

```sh
npm run build
npm run preview
```

`dist/` 是静态构建，需通过本地 HTTP 服务打开；不支持直接双击 `index.html`。开发服务器和生产预览都只监听 `127.0.0.1`。依赖安装完后可断网使用；不包含 Service Worker 或安装式离线缓存。

## 计算模型与数值规则

- 图包含输入节点 `{id, kind: "input", value}`，以及计算节点 `{id, kind: "compute", op, deps}`。
- ID 为 1–32 位 ASCII 字母、数字、下划线或短横线，首位必须为字母；拒绝原型相关保留字。ID 必须唯一；仅接受 DAG。
- 加法 `add(a,b)`、减法 `subtract(a,b)=a-b`、乘法 `multiply(a,b)`、最小值 `min(a,b)`、最大值 `max(a,b)` 均为**有序二元**；绝对值 `abs(a)` 恰好一元。同一依赖重复出现合法，如 `add(x,x)`。
- 使用 JavaScript IEEE-754 双精度数；拒绝 NaN、Infinity、非数字输入和计算溢出。下溢按 JavaScript 规则得到次正规数或零。超过安全整数范围可能舍入，不承诺精确整数代数。
- 采用数值 `===` 比较，不使用 epsilon；`0.1+0.2` 与 `0.3` 视为不同。正负零统一视为零。数值显示会舍入，JSON 导出保留原始数字精度。
- 拓扑排序使用 Kahn 算法，去重入度边，保留运算参数顺序。添加、修改、删除均先验证依赖、环和数值，再原子替换状态；删除被引用的节点会失败。
- 冷启动与任何图编辑都**完整重建缓存**。每个计算缓存记录有效标记、依赖值向量和输出值；图签名禁止修改图后继续沿用旧缓存。失败的更新批次不修改之前的有效状态。

## 三种策略

| 策略 | 执行条件 | 稳定输出之后 |
| --- | --- | --- |
| Full Recompute | 每批按拓扑顺序执行全部计算节点，包括无变化批次 | 继续完整执行 |
| Dirty Propagation | 从实际变化输入标记全部后代，执行这些计算节点 | 仍执行受影响的后代 |
| Change Propagation | 实际变化输入启动传播；仅当直接上游输出改变时执行 | 截断此路径；其他父节点变化仍能触发计算 |

批量更新先一次性写入所有输入，再按拓扑顺序执行。多父节点、共享后代每批最多执行一次；重复赋相同值不会触发增量传播。三种调度规则共享运算和追踪代码，分别决定执行集合，不互相消费计算结果。

对 V 个节点、E 条依赖，排序、脏标记和变化调度均为 O(V+E)；缓存与真实运算另计。v0.1 为追踪和检查仍扫描完整图，减少运算次数不等于省去扫描和复制成本。

### 具体例子：4 次、3 次、1 次

默认 **Stable Output**：

```text
x=-2 → a=abs(x)=2 → b=a+y=5 → c=b*y=15
                         y=3 → u=abs(y)=3 （独立分支）
```

把 `x` 改为 `2`：

- Full 执行 `a,b,c,u`，共 **4 次**。
- Dirty 执行 `x` 的后代 `a,b,c`，共 **3 次**，独立分支 `u` 使用缓存。
- Change 执行 `a`，输出仍为 `2`，因此 `b,c` 传播截断，`u` 不受影响，共 **1 次**。

所有节点最终数值一致。独立验证的额外计算不计入被比较策略的成本。

## 操作示例

1. 默认实验将 `x` 从 `-2` 改为 `2`，点击“计算批次 · 比较三种策略”。一次运行即可查看同初态、同批次的三策略统计及验证结果。
2. 点击“单步”，或选择间隔后“播放”。表格来自真实执行记录，包括节点 ID、运算、依赖值、旧值、新值、输出变化、缓存原因与执行顺序。图中使用文字、边框样式和颜色共同区分状态。
3. “暂停”停止回放定时器；切换策略从同一批次开头回放对应 trace。“重置实验”恢复最近载入或编辑完成时的输入、图和有效缓存，并清除旧证据。
4. 修改输入草稿会停止回放并清除旧统计和验证证据；“验证当前批次”会真实计算当前草稿。批次提交后，已选输入的节点编辑器同步到新值。修改多个输入再计算，作为一个原子批次；上批 trace 尚未播放完也可开始新批次，新计算从上批已提交的最终状态开始。每批初态和实际更新值均记录在验证复现数据中。
5. 点击图节点或编辑面板选择节点，编辑运算与依赖；“添加新节点”用于新增。修改后建立新的实验初态，原 trace 作废。键盘 Tab / Enter / Space 可选择图节点。
6. 选择 Chain、Branch、Stable Output、Large DAG 后点击“载入预设”。Large DAG 默认 80 节点、种子 2026，允许 4–1000 节点，种子范围为 uint32。
7. 导出 JSON 保存当前已计算状态的输入、图结构、格式版本、策略、预设参数和种子。尚未点击计算的输入草稿不属于已提交状态。
8. 导入 JSON 会验证版本、大小、类型、节点上限、依赖与数值，并要求实验规模参数与载入器一致为 4–1000，完整重建缓存。附加的结果与 trace 不会作为可信缓存恢复，也不会执行任何 JavaScript。

Large DAG 使用固定 PRNG 和 min/max/abs，避免大规模随机乘法导致溢出；其他预设和编辑器覆盖全部六类运算。相同规模和种子生成完全相同的图；输入参数与节点数组顺序也包含在导出中。

## 指标定义

统计针对一个**完整更新批次**，不是当前回放进度：

| 指标 | 定义 |
| --- | --- |
| 计算节点总数 N | 不包含输入节点 |
| 实际计算次数 C | 真正调用运算的计算节点次数 |
| 跳过次数 | N−C；从有效缓存复用 |
| 无关缓存 | 不属于变化输入的后代 |
| 截断缓存 | 属于变化输入后代，但上游输出稳定而未被触发 |
| 输出变化数 | 执行后数值与旧值不同的计算节点数，不含输入 |
| 执行但输出稳定 | 真实执行过、输出未变的节点数；不是缓存命中 |
| 节省比例 | N>0 时为 1−C/N；无计算节点时为 0 |
| 理论成本 | 每个运算统一为 1 成本单位，显示 C / N |

单位成本模型便于比较调度，不表示所有运算真实耗时相同。不将 UI 渲染、动画间隔、独立验证、缓存检查、图复制或拓扑扫描混入运算次数；不展示容易误导的墙钟速度排名。缓存命中记录也保留在 trace 中，因此 trace 条数不等于实际计算次数。

## 正确性验证与测试

`src/core/reference.ts` 的参考路径使用独立的依赖就绪扫描与独立算术实现，不使用执行器的运算函数、拓扑顺序或传播缓存。每批对初态和三策略最终结果的**全部输入与计算节点**进行比较，同时检查缓存有效标记、依赖值向量和缓存输出。失败会明确报告节点并支持导出原图、初始输入和本批更新；不作为成功展示。

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit --audit-level=moderate
```

Linux 首次安装浏览器可能需要 `npx playwright install --with-deps chromium`。已有兼容 Chromium 时，可设置 `CHROMIUM_PATH` 为浏览器可执行文件路径。E2E 自动启动 `vite preview`，必须先生产构建；不测试 Vite 开发服务器。Windows 可使用 `$env:CHROMIUM_PATH = 'C:\path\to\chrome.exe'`，通常无需设置。

- 单元：图排序、环、非法依赖、编辑、全部运算、数值边界、缓存失效、三策略计数、多输入、共享后代、稳定输出、导入和固定种子。
- 差分：150 种子 × 20 更新批次，比较每种策略全部节点与独立参考值；包含乱序节点、多父、共享/重复依赖、重复输入更新。失败仅输出合成 ID/数字，缩减到失败节点依赖锥与前一批输入，避免携带环境或身份数据。
- 复杂度：1000 节点长链、1000 节点宽分支、800 计算节点多层共享图、1000 节点随机图；断言实际运算次数，避免不稳定的时间门槛。
- 浏览器：生产页面、预设、输入、策略、单步、播放暂停重置、验证、导入导出、错误、编辑、主题、键盘、窄屏与 1000 节点。
- CI：独立 Linux / Windows Node.js 22 工作流，接入根 `CI required`；每次执行审计、静态检查、单元、生产构建与 Chromium E2E。

实际执行结果见 [VALIDATION.md](VALIDATION.md)。根隐私检查按 [隐私规范](../../docs/PRIVACY.md) 执行，公开 CI 的通用规则不能代替本地私有词表检查。

## 已知限制与扩展方向

最多 1000 节点、每个计算节点最多两条有序依赖、JSON 最多 512 KiB。计算与参考校验在主线程同步有界执行；参考路径使用独立的反复就绪扫描，最坏 O(V²+E)。无动态依赖、循环、不确定运算、用户脚本或外部数据源。图规模大时 SVG 与编辑列表会变密集，可通过容器滚动查看；追踪表仅显示最近 100 条已回放记录，完整 trace 保留在内存中。

不包含缩放拖拽、Undo、多批历史存档、Worker 后台计算或 epsilon 比较；重新加载页面后仅保留主题，实验需要自行导出。Windows 原生 CI 与用户电脑人工验收是不同证据；Firefox/WebKit、真实手机、辅助技术和浏览器峰值内存未做全面验收。

后续可按需增加 Worker、有界 trace 分页、图布局缩放、细化运算权重与批次历史；任何动态依赖或近似比较都需新增独立正确性定义和验证，不仅添加动画。
