# AdversaryLab v0.1 · 对抗输入实验室

一个完全在本地浏览器运行的算法性能对抗实验室。给定固定的输入空间、种子和评价预算，真实执行算法并搜索高成本输入；比较随机搜索、爬山和模拟退火，并以独立的小规模穷举核对排序最优成本。

面向算法学习者与实验者。不需要后端、数据库、账号或 API Key，不上传实验数据、不执行用户代码、不部署外部服务。

## 安装与启动

Windows / Linux 均需 Node.js 22.12+（也可使用 Node.js 24）和 npm。在仓库根目录执行：

```sh
cd projects/adversarylab
npm ci
npm run dev
```

访问终端显示的本地 URL（默认 `http://127.0.0.1:5173`）。停止服务按 Ctrl+C。生产预览：

```sh
npm run build
npm run preview
```

依赖有独立锁文件；不需要安装其他项目或修改根目录依赖。界面为中文，支持深浅主题、窄屏布局、数组条形图、带权有向图、最佳成本曲线、运行记录选择、策略统计和 JSON / CSV 下载。主题保存在当前浏览器，不保存实验结果；刷新前请导出。

## 实验流程

1. 选择排序或图搜索算法，设定固定输入约束及一个优化指标。
2. 选择策略、每次评价预算、随机种子和整个批次的活动墙钟时间预算。
3. 可启用三策略对比；种子以英文逗号分隔，最多 8 个互异 uint32 值。
4. 对互异排列且长度 ≤ 8，可单独启用精确穷举。它使用额外的算法执行次数，不占启发式评价预算，但占同一批次时间预算。
5. 点击开始。暂停/恢复有 Worker 确认；取消保留部分真实记录，重置则终止 Worker 并清空记录。
6. 完成或中断后选择记录查看真实最佳输入、排序输出/路径、内部计数与终止原因，再导出。

修改参数不会改变已经运行的记录或导出参数；新的开始会清空上一批结果。配置在运行/暂停期间锁定。进度达到 100% 后若仍在精确穷举，运行状态继续显示运行中，精确卡片显示独立的排列进度。

## 输入空间

- 排序：长度 0–64；互异模式始终为 `[0, n−1]` 的排列；重复模式每个值均在 `[-range, range]`，`range` 为 0–100。
- 图：2–20 个节点、0–100 条固定边（且不超过 `n(n−1)`）；简单有向图，无自环、无同向重边；整数权重在 `[0, maxWeight]`，`maxWeight` 为 0–20。允许零权重、环和不可达终点。
- 图起点固定为 0，终点为 n−1；邻接访问按终点编号升序，与输入边的存放顺序无关。三个算法都在终点实际扩展时停止，不检查终点出边。
- 图变异保持节点数、边数与权重范围；不能通过扩大实例来提高成本。

BFS 入队时标记，返回最少边数路径；DFS 为按编号升序的递归深度优先，返回发现路径，二者忽略权重，距离是边数。Dijkstra 使用真实二叉最小堆；堆依次按距离、节点编号、插入序排序。仅严格更短的距离更新父节点并入堆；等距保持原父节点；距离不匹配或已定型的条目算过期出堆，不扩展。不可达时路径为 `[]`、距离为 `null`，不会伪造到达路径。

## 成本定义

只最大化当前选定的一个计数，不把比较、移动、深度等不同量纲相加。所有 `execution.metrics` 都属于最佳输入的一次真实执行，不是整次搜索的内部操作总和。

| 算法 | 默认目标 | 其他可选目标 |
| --- | --- | --- |
| 插入排序 | 元素比较次数 | 数组写入次数 |
| 归并排序 | 元素比较次数 | 数组写入次数、最大递归深度 |
| 首元素枢轴快速排序 | 元素比较次数 | 实际交换次数、最大递归深度 |
| BFS / DFS | 节点扩展数 | 边检查数 |
| Dijkstra | 节点扩展数 | 边检查数、入堆、出堆、过期条目数 |

- **比较**：只统计实际元素值比较，不计循环、索引、边界判断。插入为 `a[j] <= key`，归并为左右首元素 `<=`，快排为元素与首枢轴 `<`。
- **移动**：数组槽位写入。插入含移位及最终 key 写入（即使写回同一位置）；归并含缓冲区写入与写回。局部变量赋值不计。快排内部也记录两次槽位写入/交换，但 UI 仅开放交换指标。
- **交换**：快排两个不同索引之间的一次交换；同索引自交换不计。快排使用首元素枢轴的就地划分。
- **深度**：根调用深度 1，含非空单元素调用；空输入为 0。不把空分区调用计入深度。
- **扩展**：实际处理的节点数，含终点，不含过期堆条目。
- **边检查**：访问扩展节点的邻接表时，每实际检查一条边计一次，包括指向已访问节点的边。
- **堆计数**：入堆含起点；出堆含过期条目，终点到达后剩余堆条目不再出堆。过期条目单独统计。

这些是具体实现的操作成本，不等同于机器耗时、峰值内存或所有实现的理论复杂度。部分指标可能在特定固定空间中为常量（例如相同长度下的归并写入），因此未必适合区分输入难度。

## 三种对抗搜索策略

共同使用 Mulberry32 uint32 PRNG、同一生成器、局部变异、验证器、目标函数及预算。初始候选均使用相同种子生成，停止展示进度不会替代真正停止计算。

- **Random Search**：每次独立随机生成完整合法输入，保留历史最好值。
- **Hill Climbing**：从当前输入变异，仅接受成本不下降的候选；成本相同也接受，无自动重启，可能停在局部最优。
- **Simulated Annealing**：不降成本始终接受；降成本以 `exp((candidateCost−currentCost)/T)` 的概率接受。每次局部评价消耗一个独立随机接受抽样。按合法评价下标 `k = evaluations−1` 几何降温：`T = T0 * (Tf/T0)^(k/max(1, budget−1))`，指数夹在 `[0,1]`。要求 `0 < Tf ≤ T0 ≤ 1,000,000`；预算为 1 时只评价初始输入，无接受步骤。指数下溢时概率为 0，不进行除零。

排列变异交换两个随机位置（可能为同一位置）；重复数组变异重采样一个槽位；图变异以各 1/2 概率重采样一条边权重，或在不与其余边冲突的位置替换一条边。空输入空间仍合法，产生重复候选。

### 统一预算与终止

| 事件 | 生成数 | 拒绝数 | 评价数 | 后果 |
| --- | --- | --- | --- | --- |
| 合法新候选 | +1 | 0 | +1 | 真实执行目标算法 |
| 合法重复候选 | +1 | 0 | +1 | 重复数 +1，仍重新执行，不用缓存冒充评价 |
| 非法候选 | +1 | +1 | 0 | 丢弃，达到生成上限则停止 |
| 生成异常 | +1 | 0 | 0 | 异常数 +1，error 终止 |
| 评价异常 / 非法成本 | +1 | 0 | +1 | 异常数 +1，error 终止，不接受该值 |

每策略、每种子独立分配 1–20,000 次评价；生成上限为评价预算的 10 倍，防止验证拒绝造成无限循环。标准生成器和变异保证合法，拒绝机制仍有故障注入测试。`budget` 表示用尽评价预算，不表示证明全局最优；`proposal-limit`、`cancelled`、`timeout`、`error` 均单独记录。

Worker 每批最多 32 个搜索步骤或 64 个排列；批间处理命令并检查时间预算。暂停确认之后移除调度，不做评价；恢复沿用原 PRNG 和状态，暂停时间不计入活动墙钟。取消确认后停止后续步骤，保留最后完整评价。取消命令遇到已完成的任务不改写其终止原因。重置终止旧 Worker，消息 ID 防止旧任务覆盖新任务。未响应取消 1 秒后直接终止 Worker，显示取消确认超时；故障/强制终止仅保留最后确认检查点，明确说明未确认操作数未知。

整个批次活动墙钟上限 30 秒（默认 15 秒），包含任务调度与精确验证，检查在有界批次边界，可能超过上限一个批次。正常用尽评价预算时相同参数和种子可复现；提前超时的部分结果会随设备与调度变化。图的遍历顺序、候选序列、接受规则均不读取渲染时钟。

## 精确穷举与启发式的区别

精确器从升序排列开始，使用独立的字典序后继枚举，不调用搜索器、PRNG、变异器或搜索最佳答案。每个排列都真实执行排序算法；只有完整遍历全部 `n!`（0! = 1）后才发布全局最大成本、最佳输入和比例。测试使用另一个递归排列枚举器及独立排序成本计算器对照。

启用精确验证即建立 `pending` 任务，所有启发式结束后才开始枚举；在搜索阶段提前取消或超时也保留零次枚举及真实中断原因。取消、超时、内部限制或异常中止时 `complete=false`、`optimum=null`、`best=null`，即使已经观察到高成本也不能宣布最优。比例为启发式最佳成本 / 已证明最优成本；最优成本为零且启发式也为零时约定为 1，异常非零分子不返回比例。图、重复数组或 n>8 不提供精确最优声明。

## 多种子与导出

单种子结果与多种子总体统计明确区分。每个策略、种子的参数、评价次数、最佳输入、真实执行计数、曲线检查点和终止原因均保留。汇总的最高成本、均值和总体标准差（除以样本数，不是无偏样本估计）只包含正常 `budget` 结束的记录；实际评价总数含所有已开始的部分记录。零成本记录有效，尚无有效值时为 `null`。

超时批次可能只有部分策略/种子执行完成，不能当作完整等预算对比；界面显示记录数与预算完成数，导出保留原计划。最佳曲线保留全部严格改善点、每 `ceil(budget/500)` 次评价检查点及终点；SVG 进一步确定性抽稀到约 600 点/记录，导出保留底层记录。

JSON 的 `adversarylab/v0.1` 包含配置、成本语义、计数规则、图规则、全部记录、统计口径、精确状态和批次终止原因。CSV 使用 UTF-8 BOM 与双引号转义，保留可解析的嵌套 JSON 字段、同一批次参数、实际执行计数及终止原因。无记录的启动故障也能导出错误状态，不伪造算法结果。只支持结果导出，当前没有导入/自动保存功能。

## 示例实验

选择插入排序、互异排列 n=8、比较次数、预算 1,000、种子 42，启用全部策略和精确穷举，退火温度 10 → 0.05。实际核心运行结果：

| 策略 | 实际评价 | 最佳比较次数 | 完整穷举最优 | 比例 |
| --- | --- | --- | --- | --- |
| Random Search | 1,000 | 28 | 28（40,320 排列） | 100% |
| Hill Climbing | 1,000 | 28 | 28 | 100% |
| Simulated Annealing | 1,000 | 28 | 28 | 100% |

最佳输入可能不唯一，不能从某个逆序数组的理论值替代真实运行。换成归并排序、缩小预算或使用多种子，观察三策略差异；图实验可选择 Dijkstra 的过期条目数作为目标，研究重复距离改善造成的堆成本。

## 资源边界、限制与后续

最多 24 次搜索（3 策略 × 8 种子）、480,000 次计划评价，逐次执行；精确最多 40,320 排列。去重只保留当前搜索最多 20,000 个键；图键用无冲突 UTF-16 编码（最多 100 码元/键，字符数据约 4 MB），排序键用有界整数数组 JSON（字符数据约 13 MB 上界），不保存全部候选或排序 trace。历史点数受最大操作成本与检查点频率共同限制。浏览器对象开销、DOM、垃圾回收和进程峰值内存不作为精确测量指标，也不保证低内存设备不受浏览器自身限制。

本版只研究这些具体算法及固定整数空间；没有图全空间最优证明、连续优化、自定义代码、算法时间拟合或一般程序性能证明。有限种子不能证明某策略普遍优越；默认指标在小空间中可能很快饱和。大批次可能因 30 秒上限提前结束。Firefox/WebKit、用户电脑人工验收和真实手机尚未验证；已提供原生 Linux/Windows Chromium CI。

后续可按需要增加独立图小空间穷举、更多受控局部变异、重复种子的配对差异区间、结果导入和可审计的执行 trace；仍保持输入约束与真实计数边界。
