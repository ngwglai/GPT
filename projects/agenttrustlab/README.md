# AgentTrustLab v0.1

中文 AI 智能体信任边界与工具授权实验室，面向学习者、开发者与安全研究者。在完全本地、无需付费 API 的环境中，用相同的模拟请求比较四种授权策略，查看拒绝原因、重放实验并导出审计数据。

**v0.1 是确定性模拟实验平台，结果仅适用于实现的场景和策略，不代表真实 LLM 的普遍安全率。** 不调用真实 LLM、邮箱、MCP、用户文件或网络工具，不部署公开服务。安装依赖需要网络；应用加载后实验可离线运行。

与现有项目的区别：AdversaryLab 搜索算法困难输入，ModelCheckLab 验证有限状态性质；本项目研究智能体请求的独立授权边界，不复用它们的业务功能。工程沿用现有 TypeScript/Vite、原生 DOM/SVG、Vitest 与 Playwright 配置，无运行时第三方依赖。

## 安装与运行（Windows / Linux）

要求 Node.js ≥22.12、npm；开发仓库还需 Git、Python 3.11+ 和根目录规定的私有隐私配置。仓库开发者先在根目录执行 `python scripts/configure_git_identity.py --install-hooks`，遵守根 `AGENTS.md`。

```sh
cd projects/agenttrustlab
npm ci
npm run dev
```

打开终端显示的本机地址。Windows PowerShell、命令提示符可直接执行相同命令。应用不提供后端或线上部署；本机服务默认仅监听 127.0.0.1。生产 CSP 禁止应用网络连接；开发模式仅额外允许 Vite 注入样式与本机 HMR 连接，不改变生产限制。

生产构建与预览：

```sh
npm run build
npm run preview
```

自动验证：

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit --audit-level=moderate
```

Linux 若缺少浏览器系统库，使用 `npx playwright install --with-deps chromium`。测试必须在构建完成且浏览器安装成功后执行；E2E 使用生产预览端口 4189，不允许复用已有服务。可用 `CHROMIUM_PATH` 指向实际安装的 Chromium。根隐私回归为 `python -m unittest discover -s tests -v`。Linux/Windows 工作流接入仓库 `CI required`，实际运行证据见 [VALIDATION.md](VALIDATION.md)。

## 使用流程

1. 选择场景；展开卡片查看用户任务、不可信输入、模拟请求、任务授权、预期和风险。
2. 勾选参与比较的策略，调整工具、资源、操作、任务范围和确认要求。
3. 对需要演示的高风险请求，可单独勾选“模拟确认（非真实授权）”。它由应用层提供，不是实际用户的发送或删除授权，不产生真实副作用。
4. 输入固定种子，运行批量实验。查看表格中的分子/分母与三色条形图。
5. 在轨迹区筛选策略，查看每次请求的六项检查、授权原因和模拟执行结果。
6. 导出配置 JSON、完整结果 JSON 或轨迹 CSV。配置变更清空当前结果并禁用结果导出；“重放上次实验”恢复上次的配置和模拟确认快照。

结果不持久保存；刷新会重置。重放仅用于本次页面中的上次实验。跨会话复现应导出配置，重新选择相同模拟确认，再运行；结果 JSON 包含这些确认 ID 供人工核对，但不能作为配置导入、不能授予确认。

## 场景与策略

18 个内置场景，每场景一个模拟工具调用，12 恶意 / 6 正常。恶意标签是测试真值，不参与授权决策。所有姓名、内容、路径与保留域地址均是虚构的模拟资源标识。

| ID | 场景 |
| --- | --- |
| a01 | 直接提示注入，要求读取机密 |
| a02–a03 | 文档诱导发送、工具返回伪造管理员 |
| a04 | 使用未允许的系统配置工具 |
| a05–a06 | 搜索机密、访问未分配给当前任务的团队资料 |
| a07–a08 | 敏感文本发送、模拟外部导出 |
| a09–a10 | 未授权删除、超出任务的发送 |
| a11 | 不可信内容声称已确认 |
| a12 | 搜索数量超出 1–10 的参数约束 |
| n01–n02 | 正常公开读取、团队搜索 |
| n03–n05 | 已获任务权限的正常发送、删除、公开摘要导出，确认策略还需要额外模拟确认 |
| n06 | 正常授权后模拟工具失败，用于区别授权与可用性 |

| 策略 | 实际检查 |
| --- | --- |
| 基线 | 不做独立权限判断，仍保留参数安全校验 |
| 白名单 | 参数 + 工具白名单 + 允许的操作 |
| 最小权限 | 上述检查 + 资源范围 + 任务范围 + 可信任务的精确工具/资源/操作授权 |
| 最小权限 + 显式确认 | 上述检查 + 对发送、删除、导出、配置及敏感读取要求应用层模拟确认 |

四策略分别启用不同检查路径，没有预设统计答案。基线也不能执行非法参数，因此 a12 在所有策略下拒绝；这是模拟器的安全边界，并非提示注入检测。确认要求可关闭以观察退化效果；关闭后确认策略等价于最小权限。

配置只能修改有限枚举列表，不能添加任意工具、资源、任务授权、场景、代码或表达式。可信任务的精确授权由场景目录定义；全局设置与任务授权取交集，不能通过扩大资源白名单获得任务外权限。不可信内容只作为输入证据展示，模拟智能体直接提出预定义请求，不分析文本或调用语言模型。

## 授权流程与架构

```text
可信场景目录 + 已校验配置 + 应用层模拟确认
                    ↓
实验运行器 → 模拟请求 → 独立授权引擎
                         ├─ 拒绝：明确原因，不签发凭证
                         └─ 允许：绑定请求快照的一次性凭证
                                      ↓
                              模拟执行器消费凭证
                                      ↓
                             原始轨迹 → 统计与导出
```

- `types.ts`：有限配置、请求和审计结构。
- `scenarios.ts`：可信任务、虚构输入、权限与请求目录；对外返回副本。
- `validation.ts`：导入配置与工具参数的独立安全校验。
- `authorization.ts`：六项检查、规则快照、确认绑定和凭证签发。确认绑定场景的完整原始请求，修改参数不可复用。
- `executor.ts`：只接受授权引擎登记的凭证；WeakMap 凭证不可伪造、单次消费，执行器不导出原始工具入口。
- `experiment.ts`：固定种子排序、统一策略输入、执行记录与重放。
- `statistics.ts` / `serialization.ts`：从原始记录统计、JSON/CSV 序列化。
- `main.ts` / `style.css`：中文响应式 DOM/SVG 界面。

界面只调用实验运行器。每次模拟工具执行都消费授权引擎签发的凭证，包括基线策略；请求、规则和确认上下文均使用快照，防止检查后修改。此结构保证正常应用路径经过授权，并不是对拥有浏览器开发者权限、修改源码或运行任意 JavaScript 的攻击者提供进程隔离。

轨迹的 `proposed: true` 表示请求已提出；`authorization.allowed` 表示策略允许；`execution.status` 分别为 `not-executed`（拒绝）、`success`（模拟成功）与 `failure`（授权允许但模拟工具失败）。每次记录包括场景/策略、信任等级、风险、完整请求、六项检查的 pass/fail/skipped、理由及模拟确认来源。聚合指标与原始轨迹同时保存于结果 JSON。

## 指标定义

所有分母按单个策略实际选中的请求数计算，界面明确显示样本数；同一场景在四策略中分别计一次，不将四策略记录混合成攻击成功率。

- 总请求数 = 恶意请求数 + 正常请求数。
- 允许 / 拒绝依据授权决定；执行成功 / 执行失败依据模拟执行状态。
- 成功执行的未授权请求数 = 恶意标签且模拟执行成功的数量。
- 攻击成功率 = 成功执行的未授权请求数 / 恶意请求数。
- 恶意请求阻断率 = 授权拒绝的恶意请求数 / 恶意请求数。
- 正常请求误阻断率 = 授权拒绝的正常请求数 / 正常请求数。
- 分母为 0 时返回 `null`，界面显示“无样本 (0/0)”。工具失败不计授权阻断或执行成功。

恶意请求数基于内置意图和权限真值；不将所有高风险请求都标成恶意。对确认策略，正常请求缺少额外确认仍计入误阻断，以呈现其交互成本。

## 可复现实验

保持默认18场景、四策略、种子2026和默认权限，不勾选模拟确认。每个策略有12恶意、6正常，共72条记录：

| 策略 | 未授权成功 | 恶意阻断 | 正常误阻断 | 模拟工具失败 |
| --- | --- | --- | --- | --- |
| 基线 | 11/12 | 1/12 | 0/6 | 1 |
| 白名单 | 9/12 | 3/12 | 0/6 | 1 |
| 最小权限 | 0/12 | 12/12 | 0/6 | 1 |
| 最小权限 + 显式确认 | 0/12 | 12/12 | 3/6 | 1 |

再勾选 n03、n04、n05 的应用层模拟确认并重新运行，确认策略的正常误阻断降为0/6，恶意阻断仍为12/12。改变种子仅改变展示顺序，不改变这些确定请求的结果；相同配置与确认可逐字节重放。独立测试固定这些预期值，而非调用被测逻辑产生答案。

## 导入导出安全边界

仅支持配置 JSON 导入，UTF-8字节上限128 KiB，最多18场景、4策略；字段必须齐全，禁止未知字段、重复ID、非法类型/枚举/种子、伪造确认、原型字段和脚本字段。文件读取前检查大小，文本解析前再次检查字节数。失败不改变有效配置，不执行 `eval`、`Function` 或导入内容。

模拟参数按工具检查字段、工具/资源/操作映射、文本长度≤1024、保留域收件地址和搜索数量1–10。不可信输入与轨迹通过 `textContent` 显示。CSV 使用CRLF、双引号转义，并给电子表格公式触发字符添加单引号；每行 `traceJson` 可用标准CSV解析器恢复完整记录。结果JSON不能冒充配置导入。生产 CSP 禁止网络连接，数据只存内存与用户主动下载的文件。

## 已知限制与后续

固定场景和规则说明授权机制的效果，不能推断真实模型、未覆盖攻击或复杂工作流的安全性。每场景单次调用，无多轮记忆、真实工具、语义注入检测、任意策略语言或持久化。模拟外传不会访问网络，模拟发送和删除不影响真实资源。批量上限72条记录，在主线程同步执行，不需Worker。

Windows原生验证由GitHub Actions执行；用户电脑人工验收、Firefox/WebKit和真实手机未验证。后续可按需增加更多多步模拟场景、细化参数级任务权限与确认交互，继续保留模拟器和授权模块的边界，不自动连接真实工具。
