## 实际失败与纠正

1. 一次 npm 命令误从仓库根目录启动，因没有根 `package.json` 返回 ENOENT；这是工作目录错误。改到项目目录成功，根目录产生的空锁文件已删除；不修改业务源码来处理此问题。
2. E2E 新增后的类型检查发现 Playwright matcher 要求 Record/数组类型，而 `Experiment` 没有索引签名；修改测试的比较方式，未绕过检查。
3. 首轮生产 E2E：10 通过 / 2 失败。下载跨运行时检查把 Node 与 Chromium 的 exp/log 结果要求逐位相同，实际只是约 10⁻¹⁶ 舍入差；改为显式绝对容差 5×10⁻¹²，仍逐条检查所有字段与数组长度。同运行时重跑继续要求逐字节相同。README 明确跨引擎边界。
4. 另一失败是测试种子 1 并没有让保序 Brier 变差（实际改善）；用已计算确认的种子 3 测试真实变差路径，保留所有正常种子，不更改生成器或算法。随后完整 12/12 通过。
5. 自动审查的数值问题确实可复现：过度自信、200 样本、种子 32 在梯度接近阈值时，原 Armijo 判断要求的改善低于目标函数舍入误差，回溯到不可分辨的参数更新而重复到 100 次。改用避免相消的等价交叉熵形式，给线搜索增加几个 ulp 的显式容差，保留严格的 10⁻⁸ 梯度阈值，并对完全相同的参数更新立即报告精度极限。新增独立梯度回归、三个场景各 100 固定种子及生产页面回归；最终 119 单元/13 E2E、类型/lint/build/审计通过。
6. 身份审查意见先后引用 08540bd 与 ebc52a7；`git rev-list HEAD` 确认两者均不在本 PR 祖先中，PR 实际提交列表仅为本次经过主动私有检查的提交。实际提交范围检查仍为 0 命中；未根据非 PR 对象改写历史或放宽身份规则。
7. 第二轮审查复现精确分箱边界问题：22 箱、p=15/22 时乘积为 14.999999999999998，原 floor 分配到14号箱，与左闭区间声明不符。改为先生成共享边界数组、二分比较分配；不加 epsilon。新增22箱回归，以及所有2–30箱的每条精确边界和前后相邻IEEE754数值检查。最终121单元、13生产E2E及类型/lint/build/审计通过，仍以最新修复头完整CI为合并门槛。
