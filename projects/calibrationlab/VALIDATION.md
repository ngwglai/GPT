## 实际失败与纠正

1. 一次 npm 命令误从仓库根目录启动，因没有根 `package.json` 返回 ENOENT；这是工作目录错误。改到项目目录成功，根目录产生的空锁文件已删除；不修改业务源码来处理此问题。
2. E2E 新增后的类型检查发现 Playwright matcher 要求 Record/数组类型，而 `Experiment` 没有索引签名；修改测试的比较方式，未绕过检查。
3. 首轮生产 E2E：10 通过 / 2 失败。下载跨运行时检查把 Node 与 Chromium 的 exp/log 结果要求逐位相同，实际只是约 10⁻¹⁶ 舍入差；改为显式绝对容差 5×10⁻¹²，仍逐条检查所有字段与数组长度。同运行时重跑继续要求逐字节相同。README 明确跨引擎边界。
4. 另一失败是测试种子 1 并没有让保序 Brier 变差（实际改善）；用已计算确认的种子 3 测试真实变差路径，保留所有正常种子，不更改生成器或算法。随后完整 12/12 通过。
