# AI 实验室：可视化与部署

线上入口：[AI 自动玩家实验室](https://ngwglai.github.io/GPT/RogueSurvivor/ai.html) · [原游戏](https://ngwglai.github.io/GPT/RogueSurvivor/)。原游戏导航与实验室顶部提供互相跳转入口。

## 观看一局

选择 Legacy、Combat V3 或 Build V4，再选择地图、角色、标准/无尽、种子和速度，点击“开始新对局”。AI 自动移动、自动攻击、使用实际技能、选牌、消耗合法刷新次数及使用星火复活。标准模式击败最终首领后结算；选择无尽模式可从头进行无尽挑战。重复相同配置可观察不同策略的行为差异。

可随时暂停、继续或重新开局。后台标签页自动暂停，回到页面后手动继续。点击开始会解锁浏览器音频，播放原地图音乐、战斗音效及原角色、怪物、弹道和特效；音量与开关仅影响实验室，不保存到手动游戏设置。

0.5/1/2/4/8倍控制每秒请求执行多少个逻辑步，`World.step` 始终使用 1/60 秒，AI 仍每 0.05 游戏秒决策。不扩大 dt、不跳碰撞、不跳敌人或改变成长。每渲染帧最多处理48步并分配约8ms逻辑预算；单步无法中断。浏览器执行不及时就放慢模拟，限制追赶积压，不向游戏时钟补加未执行时间。底栏显示约0.75秒窗口测量的实际模拟速度，并提示性能受限。音乐保持正常音高。

“快速模拟30秒”是原按钮的异步实现：排入1800个完整逻辑步，分帧执行并持续绘制，可暂停。途中切换倍速取消尚未执行的批次，之后按新倍速继续。战败/复活动画也使用原 presentation API 完整推进，不计算为战斗存活时间。

## 观察真实决策

- 展开“AI决策观察”，可查看策略、状态、实际移动目标、决策时刻、累计决策次数，以及候选路线风险中占比最高的来源。它是策略的风险估算，不是伤害归因。
- 勾选“显示实际路线图层”：灰线是实际评估的候选，虚线是评估过的冲刺路线，浅绿线/箭头是实际选中的路线和方向，金色标记是实际目标，淡红虚线是已评估的范围预警。坐标使用原画面的玩家相机。预测是算法近似，不承诺真实未来敌人轨迹。
- Legacy 没有路线搜索，只显示其实际方向、目标和原危险阈值；不伪造候选路线。
- 卡牌表保留各候选的原始评分，突出最终选择；下拉框可查看当前局历史和合法刷新。评分提示使用策略已有的 `reason`，不同策略分数尺度不能直接横向比较。没有另造自然语言解释或拆分不存在的收益项。
- 技能日志来自 `World.cast` 返回成功之后，记录实际时间、技能、槽位和原引擎射程限制后的目标；不将AI尝试释放等同于施法成功。

`Policy.setDebug` 开关只控制采集，不参与选择；候选轨迹与风险分量在原评估函数内记录，不再运行第二套策略或采样随机数。只保存一份最近的移动决策；关闭面板及图层后不构建预测轨迹和风险明细。UI约150ms更新一次，逻辑决策频率不变。

## 对局记录与隔离

使用独立 localStorage 键 `rogue-survivor-ai-lab:v1`。每局记录存活游戏时间、波次、击杀、Boss、等级、输出和承伤、生命、武器等级、技能、最终属性、卡牌构筑及结算原因。可导出当前局或历史局 JSON。进行中的记录不具备恢复游戏功能。

最多保留12局，序列化UTF-16预算1MiB，每局最多最近240次选择/刷新和160次成功施法；累计次数单独保留。旧记录按数量/容量淘汰。游戏结束、重开、页面退出和每30秒墙钟时间保存检查点。退出保存不保证应对浏览器崩溃；存储配额不足时显示提示，仍可导出。导出同样有日志上限，不是无界帧级录像。

实验室不导入手动存档服务、不打开手动 IndexedDB；不会读取、覆盖手动游戏的进度、资源工坊或设置。默认角色初始技能与 PR #52 公平基线一致，不增加玩家属性、不改变敌人数值。

## 代码与测试

- `src/ai/session.ts`：完整对局的固定步驱动，复用 `AIController` 和三个既有策略。
- `clock.ts`：倍速、CPU预算、暂停及追赶限制。
- `diagnostics.ts`、策略内部采集、`overlay.ts`：真实决策快照与独立画布。
- `controller.ts` 的 `ObservedWorld`：只观察原 `cast` 结果，记录合法选牌与刷新。
- `history.ts`：有界本地记录、序列化与配额失败处理。
- `demo.ts`：`GameScene` 子类，仅替换模拟时钟，继续调用原绘制/动画；音频复用原 `AudioEngine`。

## 静态部署

沿用 `.github/workflows/pages.yml` 的聚合站点，不创建服务或数据库。Vite 已以 `index.html` 和 `ai.html` 为两个入口，`base: './'`，跳转与资源均为相对路径，构建后同时保留于 `_site/RogueSurvivor/`。组装阶段检查两个HTML存在，并保留其他项目的 Pages 文件。合并到main后，现有流水线验证再发布。

已知限制：高密度无尽和软件渲染会低于请求倍速；高级诊断有额外采集开销。桌面 Chromium 是主要验证目标；未声称已在所有实体浏览器/移动设备长期实测。原策略的寻路和构筑近似限制保持不变，详见 [AI-PLAYER.md](AI-PLAYER.md)。
