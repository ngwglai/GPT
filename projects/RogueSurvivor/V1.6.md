# v1.6《星火重燃》

在v1.5上迭代：三角色动态美术、战败演出与Boss星火复活。保留角色身份、三角色属性、五武器六技能、70项卡牌、四地图、七Boss、波次规则、成长倍率、经验与奖励规则，以及800敌人／1200弹幕／240区域预算。

## 动态角色与实际生成方式

当前环境提供OpenAI内置`image_gen`静态图片生成，**没有可调用的原生GIF／视频生成接口**。本版没有声称使用不存在的GIF模型：实际生成三张8列×7行的连续动作母图，逐格具有不同的肢体、头发和服装姿态，再编码GIF预览和无损WebP精灵图。不是用单张静态图平移、缩放或旋转凑动作。

实际交付：**原生GIF模型输出0组；逐帧美术转换的GIF动画21组，游戏精灵图21张，共168个绘制帧槽位**。每个动作8帧，与任务书建议帧数不同；为可靠的固定格转换采用统一帧数。GIF的时间精度为10ms，游戏使用精确的帧率。

## 素材规范与处理

日系可爱幻想、2.5～3头身、清晰深色轮廓、赛璐璐上色与少量柔光；青绿／白金／银紫分别区分三角色。固定三分之四视角，面朝右，代码水平翻转，不制作八方向。动态动作保持角色发型、服装及武器一致。

来源为本次内置OpenAI图像生成，无外部付费API或商业游戏素材。共6次图片生成：三张初版母图、两张修复母图、一张三人立绘。守卫及法师初版施法光效越界，已重新生成，交付母图只保留修复后的版本。源图清理平台附带元数据，仅保留图像像素；不包含账号／会话信息。

- `art-source/v1.6/*-source.png`：三个最终动作母图及一张透明三人立绘。
- `art-source/v1.6/*-contact.webp`：各角色七行动作总览，按待机、奔跑、闪避、施法、受伤、战败、复活排列。
- `art-source/v1.6/*-qa.json`：每帧边界、帧数、帧率、不同帧计数和尺寸范围。
- `public/assets/v1.6/characters/<角色>/`：七张1536×192无损WebP条带、七个GIF预览、192像素静态回退、头像及透明立绘。
- `tools/prepare-v16-characters.py`：Pillow处理脚本（`python -m pip install Pillow`）。执行`python tools/prepare-v16-characters.py ranger knight mage portraits`重建。

动作母图先按固定8×7网格提取，清除品红背景与边缘，整名角色统一缩放、对齐脚底至192画布的170像素基线，保留原绘制姿态及格内水平位置。脚本拒绝空帧、左右越格、输出边缘裁断及动作缺帧；GIF逐帧验证8帧，没有通过复制同一姿态补足。运行资源直接使用无损WebP，避免GIF调色板损失。`python tools/prepare-v16-characters.py check`可复检21个GIF的帧数、循环策略、不同姿态和颜色保真度；不透明像素RGB平均绝对误差为5.59～6.24／255（详见`validation/v1.6/gif-check.json`）。立绘在透明分隔处裁切并留边。

预览：[莉芙待机](public/assets/v1.6/characters/ranger/idle.gif)、[莓露待机](public/assets/v1.6/characters/knight/idle.gif)、[露娜待机](public/assets/v1.6/characters/mage/idle.gif)；[莉芙完整动作](art-source/v1.6/ranger-contact.webp)。GIF中的非循环动作由查看器决定播放／停留方式，游戏状态机明确停在战败末帧。

## 动画状态机与资源工坊

`data/characterAnimations.ts`统一帧率／时长／优先级／资源ID；`render/characterAnimation.ts`管理循环、单次、方向、事件和结束恢复。优先级为：战败＞复活＞受伤＞闪避＞主动施法＞移动＞待机。低优先事件不会排队到高优先动作结束后补播。普通自动攻击不触发施法，Q/E/R成功释放立即触发视觉动作。移动姿态只在实际执行固定模拟步后更新，无模拟步的渲染帧沿用上次观察；60／120／144Hz回归确认连续奔跑均能覆盖8帧，不会反复回到待机。

角色选择使用独立CSS精灵帧时钟展示待机，与战斗时间无关；减少动态效果的系统偏好下显示静帧。战斗动作只加载当前角色七条带，解码Promise和Phaser纹理缓存复用；不每帧加载、不预加载其他角色全部动作。

21个稳定动作ID为`animation.<角色>.<动作>`，加入原有资源工坊与资源清单。可替换单张PNG/WebP或配置精灵图尺寸／帧数／帧率；单次动作按标准时长重采样帧，避免自定义动画改变死亡／复活规则。旧`player.<角色>`自定义图片优先，仍然有效；没有自定义根图时使用各动作图。动作图失败则回退静态角色；静态图亦缺失则使用原矢量回退。所有替换只影响显示，不改变碰撞体、距离或伤害。

## 战败、星火与复活

生命归零进入`dying`，立即冻结战斗与波次；画面保留。独立演出时钟播放完整战败并停留末帧，之后有星火进入`revive`选择，无星火进入`dead`结算。手动暂停、页面失焦或隐藏同样暂停演出。复活选择不设倒计时。

**每只正式、带出场序号且可奖励的Boss，在死亡结算时获得1次星火。** 初始0，可累积；普通怪、临时召唤物、无奖励镜像及重复处理不发放。保存已奖励的正式Boss序号作为高水位；现有调度一次仅有一名正式Boss，因此无需无限增长的已领取列表。第5／10／15／20波顺序不变，最终Boss奖励后仍正常通关；继续无尽保留剩余次数。无固定游戏上限，仍受既有有限数字与存档校验保护。

点击“重新点燃星火”先原子化保存`reviving`状态与扣次，再播放完整1秒复活动画。已扣次阶段恢复不会再扣一次。动画结束恢复最大生命的**50%**，启动**3秒无敌**；冲刺不会缩短保护。清除角色**240像素**内的敌方投射物，保留远处敌弹、友方弹、敌人和区域；不击杀敌人。保留当前波次剩余时间、生成预算、Boss、构筑、经验及技能冷却。此前尚待结算的升级会在复活完成后照常出现。

“结束本次远征”直接结算，不消耗星火。HUD显示剩余星火，Boss击败提示“获得星火×1”；结算增加累计获得／使用／剩余统计。极端情况下玩家与最终Boss同帧死亡，以通关优先。

复用v1.5本地CC0采样：战败用失败声、复活确认用绽放声、站起用稀有奖励声、Boss星火用晶体声。没有增加外部素材或新授权。战败与复活阶段BGM降至设置音量的35%，保持同一曲目进度，成功后恢复；手动暂停／隐藏暂停，营地／最终结算停止。六首用户BGM的许可不作额外声明。

## 存档兼容与事务

IndexedDB数据库版本仍为1，Run结构升至**4**。显式迁移旧1／2／3；旧1／2仍先走既有地图和波次迁移，旧3原波次原样保留。旧存档新增星火默认0，**不按历史Boss击杀补发**；尚在场的正式Boss以后击败仍可领取一次。

新增`revival`保存剩余、获得、已用、奖励序号、演出进度与死亡次数。进入战败、等待选择、复活动画及恢复战斗均保存检查点；意外刷新可能从最近演出检查点重播，但不会重新扣次或重新生成波次。确认时存储失败回滚至选择状态，不继续演出。原有备份与非法数据校验保留，损坏存档不静默删除。

每局用`getRandomValues`生成128位稳定`recordId`（兼容没有`randomUUID`的本地HTTP页面，不消耗游戏RNG），与最多两个模式的`recorded`标志，结算在同一IndexedDB事务写入历史与终局Run；同一局同一模式刷新／重复提交不重复计入，标准通关后继续无尽可各记一次。启动时会补全“终局已保存、历史事务尚未完成”的结算检查点，仍按同一ID去重。事务读取最新档案合并，不覆盖同时产生的其他历史。新远征已占据当前槽时，迟到的旧结算不会覆盖新Run。

## 已知限制与差异

- 没有原生OpenAI GIF生成接口，实际为生成的逐帧图片转换动画；不是原生GIF模型输出。
- 统一8帧，跳跃、发饰和衣摆仍可能有轻微手绘帧差；不是骨骼动画或八方向动画。三角色动作总览和浏览器截图供审阅。
- 受伤／施法／闪避视觉时长与实际战斗效果分离，动画不延长无敌或延迟释放。
- 动作PNG母图、无损WebP与GIF预览增加仓库体积；运行时按当前角色加载并缓存动作图（切换后保留已解码角色），不下载GIF和母图。21条带约3.94MiB，每角色解码7×1536×192×4，约7.9MiB像素；全部30张新运行WebP约5.44MiB，21个GIF预览约1.32MiB。
- 未验证移动端、Safari、Firefox或人工声卡听感；Phaser既有大分块构建提示仍存在。
