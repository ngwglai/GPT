# AI 自动玩家：运行、设计与边界

AI 使用实际 `World`、正常角色和敌人数值，决策为普通 TypeScript 程序，不调用大语言模型或外部 API。手动游戏入口和存档保持独立。测试成绩、迭代与限制见 [AI-REPORT.md](AI-REPORT.md)。

## 使用

Node 22.15+；Windows PowerShell、命令提示符、Linux 均可运行：

```bash
npm ci
npm run dev
```

访问终端地址下的 `/ai.html`，选择策略、角色、地图、标准或无尽模式和种子，点击“开始新对局”。此入口复用 Phaser `GameScene` 和原战斗画面，自动移动、施法、选牌、合法刷新和星火复活；可以暂停或重新开局，不读取或写入手动游戏的 IndexedDB。“快速模拟 30 秒”逐一执行 1800 个正常固定步，跳过中间绘制后展示结果，仍执行选牌、施法、碰撞与复活动画计时；不会直接增加游戏时间或属性。默认 `index.html` 仍为原手动游戏。实验室静音；后台页自动暂停。演示按正常速度运行，不能将其软件渲染帧率等同于无渲染测试吞吐。

```bash
npm run build
npm test
npm run ai:check
npx playwright test tests/ai.spec.ts
npm run ai:benchmark -- --policies legacy,combat-v3,build-v4 --seeds 11,29,83 --seconds 1800 --workers 2 --output ../../work/ai/example
```

默认完整笛卡尔积：策略 × 地图 × 角色 × 种子。每局真实逻辑 60 Hz、决策 20 Hz；没有跳过碰撞、加速敌人计时或更改成长。`--hz 20` 仅用于复核旧脚本原来的 0.05 秒步长，不与 60 Hz 成绩混合。`--decision-hz 10` 可做决策频率消融，最终成绩使用 20 Hz。

`--balanced` 将种子依次分配到地图/角色格子，每个种子只测试一个场景，三组策略共享相同分配，便于控制时间预算并保留独立种子。`--maps forest,cavern,garden,eclipse` 选择地图；`--characters ranger,knight,mage` 选择角色；`--mode endless --seconds 7200` 运行有时限的正常无尽挑战。到达时间上限标为右删失，不写成死亡或“生存极限”。

当前实际容量以 `src/data/content.ts` 为准：800敌人、1200弹道、240领域；测试不降低容量，高密度局可能显著变慢。建议普通电脑使用 `--workers 2`，机器较弱可用1；机器执行速度不改变游戏内计时或规则。

原始每局 JSON 保留所有选择/刷新及候选分数、最终完整角色属性/武器/技能/卡牌、各来源输出、全部受击、复活、每分钟检查点和终局敌人信息。输出目录中的 `manifest.json` 记录固定调度、Node 版本和相关源码 SHA256；`--resume` 仅允许在源码及调度完全相同时恢复；验收也核对源码指纹和完整调度。SHA按字节计算，换行转换也会判不同；Windows等平台可在当前checkout重新执行benchmark→report→acceptance。更换策略必须用新目录。不要在同一输出目录混入不同实验。

```bash
npx tsx tools/ai/report.ts validation/ai-player/example ../../work/ai/example
```

`npm run ai:acceptance -- validation/ai-player/holdout` 复核本次完整验收：至少24个独立种子配对、四地图三角色覆盖、60/20 Hz、1800秒正常规则、通关至少击杀4 Boss；两种新策略必须在配对生存计分95%区间下界、符号检验、平均波次及通关数上优于旧策略。失败返回非零，不重试或剔除失败种子。

生成可阅读的 `summary.json`、本地展开的 `matches.json` 及包含全部遥测的 `runs.json.gz`（完整构筑/选牌亦在压缩档中；展开文件不入库，CSV提供简洁逐局索引）；归档写入后重新解压核对。评估器内部的估算值不是实际战斗成绩。

## 接口与隔离

- `src/ai/types.ts`：只读 `Observation`、`Policy.act()`、`Policy.choose()`。观察包含当前玩家、敌人、弹道、预警、岩石、经验、奖励、地图临时状态、当前波次、装备和构筑。排除游戏 RNG、种子、下一次生成/Boss/随机事件安排。玩家可见的倒计时、蓄力、冻结与技能冷却可以使用。
- `src/ai/legacy.ts`：从原 `tests/simulate.ts` 提取决策，原脚本不变。20 Hz 等价回归核对存活、击杀、伤害和武器，避免人为削弱基准。
- `src/ai/combat.ts`：预测和移动，不调用 `World.step` 预演真实未来，不生成随机数。可配置候选数量、预测时域、近期风险权重、保持方向和安全距离。
- `src/ai/build.ts`：静态构筑增量评价；副本中使用游戏真实重算、武器等级和伤害乘区。随机牌使用保守期望分数，不在副本中抽奖或试探 RNG。
- `src/ai/controller.ts`：适配公开 `World.choose/revive` 与合法 `refresh`，输出普通 `Input`；新策略可直接替换，不需要修改游戏规则。
- `tools/ai/runner.ts`：独立无渲染比赛驱动。只给策略观察，真实 `World.step` 执行全部动作。复活动画继续走原 presentation API。终局存档由现有验证器校验。
- `tools/ai/benchmark.ts/statistics.ts/report.ts`：并行普通工作线程、配对统计、置信区间、源码指纹和可压缩证据。

## 战斗决策

默认演示采用 COMBAT_V3 + BUILD_V3（实验名 `build-v4`）；`combat/build` 保留为第一代候选的复现实验别名。第三代移动使用 0.05、0.10、0.20、0.35、0.55、0.80、1.05、1.35 秒采样，优先近期碰撞，终极技能瞄准射程内首领；第四轮修正同轮构筑风险权重的比较基准。

移动候选为 20 个等角方向、静止及当前目标方向。每个候选检查多个未来位置；沿途调用原岩石碰撞移动函数，惩罚堵路、边界、敌群和弹道风险，同时奖励安全拾取、保持方向及进入有效输出距离。每次只执行下一小段，再读取当前状态重规划。

敌人速度根据上次观察估计，结合当前冻结、冲锋方向和预警。敌弹以相对线段最近距离评估交会，覆盖两个采样点之间的高速穿越；弯曲轨迹近似外推。范围预警调用原 `zoneContains`，区分圆、条、扇形，并计算延迟后平移和旋转。危险较高时比较冲刺路线，考虑冲刺距离、无敌长度、冷却和落点风险。预测是近似模型，不能保证全部 Boss 招式可躲。

目标以安全经验和已出现奖励为主，避开负面糖果与月蚀法阵；没有可拾取目标时在地图中部移动。当前武器影响输出距离。攻击技能按距离、冰环实际半径、敌群和 Boss 选择时机；治疗按实际缺失生命与技能治疗量；终极技能优先首领、密集敌群或高风险弹幕。使用实际存在的六技能机制，保留游戏的射程、护盾、冷却和容量限制。

## 构筑决策

评价下一张牌对以下目标的边际对数收益：群体输出、单体/Boss 输出、有效生命、持续恢复/补盾、移动能力、经验经济；残血时提高生命权重，后期降低经济权重。多个乘区的实际边际收益会随已有数值变化，暴击与暴伤、伤害与攻速自然互相影响。

武器使用注册表中的实际等级伤害、间隔和三级进化；考虑弓多箭/穿透/分裂、灵体数量/频率、火焰爆炸与持续伤害、月环减速、弧刃范围和每次补盾。伤害引用 `damageBreakdown/criticalMultiplier`，继承原有效上限、对数递减、减伤及诅咒。覆盖率、群体命中和控制触发频率为可调近似，不是从未来战斗读取的实际值。

83张牌、34条前置/互斥边的实际注册表快照见 `validation/ai-player/card-graph.json`；它是规则图，不代表每条边都能形成正收益连招。前置/互斥关系来自全部卡牌注册表，未完成机制只给折扣后的后续选择价值。有限核心估算有界衍生收益，禁止递归放大。治疗与生命卡考虑立即收益。负面三选一比较损失且不刷新；弱正面候选才使用合法刷新次数。不会额外赠牌、直接修改实战属性或提前查宝箱/洗牌结果。

## 统计解释

三组必须同版本、初始角色/地图/技能、种子、模拟上限、逻辑步长及决策频率。策略差异会改变游戏的随机数消耗次序，因此“同种子”不等于后续每一发暴击或每张候选都相同；未改游戏随机数系统去强行对齐。

分别报告胜率、到达波次、真实对局时长、击杀、Boss、伤害和受伤。通关会提前结束，不能把通关较快误判为活得较短；配对主要分数为死亡/删失前时长，通关计满测试上限（明确标为胜利计分，并不声称通关后实际存活）。同时保留原始秒数。

95% 区间采用固定统计 PRNG 的 4000 次 bootstrap，胜率给 Wilson 区间；统计 PRNG 与游戏无关。配对报告胜/负/平、双侧精确符号检验，并给按种子聚类的均值差区间。调参种子与独立验收种子分开，按地图/角色展示分层结果，不能据小样本推断所有角色或真人胜率。

死亡分类根据实际 `hurt` 回调、调用阶段及现场候选来源，保留接触敌人、附近弹道和覆盖预警。围困、边界、输出积压和低生命容量为现场启发式标签，不是经过因果实验证明的唯一原因；多个来源重叠时不能百分百确定击中者。没有修改原 `Combat.hurt` 签名或伤害逻辑。


已知待优化：当前掉落目标没有区分正面和负面抽卡，可能额外吸引AI靠近负面牌；与已避开的负面糖果不同。冻结验收期间不改此行为，报告保留这些局的实际诅咒和选择；后续版本应修正并使用新的验证种子。卡牌DPS模型也存在冻结/减速覆盖和斩杀条件的近似，见报告限制。
