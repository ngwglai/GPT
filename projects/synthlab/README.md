# SynthLab v0.1 · 程序合成实验室

完全本地的程序合成教学工具。编辑整数输入输出样例，在受限 DSL 中按 AST 节点数搜索程序，用独立目标规格寻找真实反例，重复搜索直到在指定有限域验证通过。没有后端、数据库、账号、LLM、付费 API 或外部部署。运行时不发送实验数据，不加载 CDN。

面向学习者、算法研究与小规模规格实验；不替代编译器、通用程序生成或无限域定理证明。与 ConstraintLab 的 CSP、CausalLab 的因果分析、ModelCheckLab 的状态图验证不同，本项目搜索的是表达式程序本身。

## 安装与启动（Windows / Linux）

安装 Node.js **22.12+**（推荐 Node 22 LTS）及 npm，在终端执行：

```sh
cd projects/synthlab
npm ci
npm run dev
```

按终端显示的本地 URL 打开浏览器。Windows PowerShell / CMD 使用相同命令；如 PowerShell 策略拦截 npm.ps1，可使用 `npm.cmd ci`、`npm.cmd run dev`。按 Ctrl+C 停止。项目用锁文件固定依赖，无需 Python 或 Git 即可运行已下载的项目。

生产构建与本地预览：

```sh
npm run build
npm run preview
```

首次安装需要访问 npm；安装完成后断网仍可运行实验。使用本地 HTTP 服务；不直接双击 dist/index.html，浏览器模块 Worker 需要 HTTP 来源。

## 实验步骤与四个案例

1. 选择案例，查看初始样例、运算符、常量、预算与有限验证域。
2. 点击“开始合成”，查看候选、真实统计、节点层与搜索轨迹。
3. 查看每轮反例：输入、目标输出与候选的实际输出。每轮重新枚举，不复用上一轮的等价类。
4. “有限域验证通过”只表示所有指定域输入均被检查并满足规格。可调整域后重新运行。
5. 编辑、导入、重置都会停止旧 Worker 并清除旧结论。可随时取消计算。
6. 导出 JSON 保存配置、AST、真实统计、验证计数和迭代；导入只恢复经过校验的配置，**不信任导入结果**，必须重新运行。

| 案例 | 独立内置规格 | 常量 | 运算符 | AST 上限 | 验证域 / 输入数 | 预期行为 |
| --- | --- | --- | --- | --- | --- | --- |
| Max2 | 两整数最大值 | -1,0,1 | lt,if | 6 | [-3,3]² / 49 | 相等输入先拟合 x，再发现输入次序反例 |
| Abs | 整数绝对值 | -1,0,1 | sub,lt,if | 8 | [-3,3] / 7 | 正数样例得到恒等程序，负数驱动修正 |
| Clamp | 截断到固定 [-2,2] | -2,0,2 | lt,if | 11 | [-3,3] / 7 | 下界和上界各产生反例，学习两层条件 |
| Sign | 负数 -1、零 0、正数 1 | -1,0,1 | lt,if | 11 | [-3,3] / 7 | 多次反例区分三个区段 |

所有案例只有配置和独立规格，没有预设候选 AST、答案查表或按案例名称分支的搜索逻辑。Clamp 使用 [-2,2] 的原因：整数域的 [-1,1] 截断恰好等同 Sign，为使两个教学案例目标不同而调整边界；仍可在 11 节点内合成。默认预算为总候选 2,000,000、总时间 15 秒、每轮代表 20,000、最多 16 轮、每轮最多验证 4096 输入。

目标规格可选择内置函数，也可编辑经过类型和资源校验的整数表达式 AST。规格独立于候选语法，可以使用未启用的搜索运算符和常量；规格必须在验证域上无溢出，且与所有初始样例一致。初始样例可以位于验证域之外，此时只额外要求拟合这些样例，不扩大“有限域通过”的范围。

## DSL 与安全整数语义

`src/core/dsl.ts` 定义互递归的整数 / 布尔 AST，无任意脚本执行。

```json
{"op":"if","args":[
  {"op":"lt","args":[{"op":"var","index":0},{"op":"int","value":0}]},
  {"op":"sub","args":[{"op":"int","value":0},{"op":"var","index":0}]},
  {"op":"var","index":0}
]}
```

- 整数叶节点：`int/value`（安全整数）与 `var/index`（0 为 x、1 为 y）。布尔叶节点：`bool/value`。
- `add/sub`：两个整数返回整数；`lt/le/eq`：两个整数返回布尔值。
- `and/or`：两个布尔值；`not`：一个布尔值。
- `if`：三个运算元，条件为布尔，两分支类型相同，可返回整数或布尔。
- 所有变量为整数，候选及目标规格返回整数。字段、类型、元数、未知运算符、AST 大小和输入范围均严格校验，不执行 `eval`、`new Function` 或用户 JavaScript。
- 整数范围为 ±(2⁵³−1)；加减结果超范围产生唯一语义错误值 **⊥**（内部 null），不会包装、饱和或当作普通数字。负零规范化为 0。输入整数限制为 ±1,000,000。
- 除 `if` 外所有运算符均严格传播 ⊥，包括布尔 and/or（有意不采用 JavaScript 短路语义）。`if` 条件为 ⊥ 时结果为 ⊥；否则只求值所选分支。未选分支的溢出被屏蔽。外层程序输出 ⊥ 不能拟合整数样例，也会成为验证失败。
- 同步解释器接受的 AST 最多 63 节点、32 层；搜索上限最多 15 节点。不包含循环、递归调用、乘除、状态、外部访问或浮点。

## 枚举、结构去重与观察等价的正确性

`src/core/engine.ts` 不依赖 React。按总 AST 节点数 1…N 枚举；每个运算符的子节点成本正整数分拆为 `n−1`，并按类型取已生成的较小表达式组合。变量、常量、运算符和成本分拆顺序固定，运算符配置规范化，不依赖墙钟决定候选次序（资源截断的时刻除外）。

每个 AST 的根运算符、子树节点数和有序子树元组唯一，因此不会重复生成相同结构。对于 add/eq/and/or，子树代表 ID 排序只枚举一个交换次序，记录结构剪枝；这些运算符在当前严格错误语义下交换安全。其余运算符不做未经证明的代数优化。

观察签名是 **输出类型 + 在本轮全部训练输入上的完整值向量**；值向量包括每个坐标的整数、布尔或 ⊥。为每个签名仅保留首次出现的最小节点代表；全错误或部分错误向量也必须保留，不能丢弃可能被 if 屏蔽的子表达式。

安全性论证基于以下明确假设：表达式纯、确定、无副作用；没有能观察语法、求值次数或时间的运算符；只有上述值和错误语义；成本为每个节点 1 的可加树成本。

1. 同类型的相同值向量，在任意合法单层上下文中仍产生相同向量。普通运算符按坐标严格传播错误；if 按坐标检查条件并选择对应分支，未选分支错误不影响结果。因此即使存在惰性条件，**包含 ⊥ 的精确签名**仍是合同关系。
2. 按树高归纳，将任意表达式的子树替换为同签名的最小代表，不改变当前训练向量，且成本不会增加。这些代表在父节点被枚举之前已可用。跨成本保留最小代表保持“大小 ≤ N”内可拟合程序的存在性；不声称保留每个精确成本的所有语法树。
3. 搜索按成本递增，完整处理所有较小层后才找到候选，因此其节点数对当前样例、语法、常量和树成本最小。层被预算中断则不宣称该范围无解；仅完整遍历 N 层后才能报告“有界范围无解”。最短性不等同于任意规格或无限域的全局最优。
4. 等价仅相对于本轮样例。反例加入后，**重建所有桶与签名**。不跨轮复用剪枝结果。

独立参考穷举器不使用内核或解释器，枚举小语法全部语法树，对照每种完整输出向量的可合成性与最小节点数；另比较禁用观察剪枝的搜索、BigInt 算术参考、条件屏蔽溢出用例与 50 固定种子规格。测试验证具体实现；上述合同关系与成本归纳说明优化成立的语义范围。若以后加入可观察错误种类、状态或时间的 DSL，必须重新证明或禁用该剪枝。

## CEGIS 与结论状态

先检查规格在指定域为全函数、样例与规格一致。此规格预检不算候选验证。每轮：从当前样例完整重新合成 → 按字典序逐点比较候选与独立规格 → 发现第一个差异即记真实反例并加入样例 → 重新枚举。

每次新候选都重新验证，不复用上一候选的通过计数。记录域、总输入数量、实际检查数、是否完整、反例及实际值。每轮验证状态分别为 incomplete（未完成）、counterexample（验证失败并发现真实反例）、passed（完整通过）。发现反例后的扫描是提前停止，`complete=false`；只有扫描全部输入且无差异才为 `complete=true`。

- **verified**：指定有限域完整通过；不是无限域数学证明。
- **no-solution**：当前样例、DSL、常量、节点上限内完整枚举后无解。
- **budget-exhausted**：候选、代表、时间、迭代或验证预算耗尽；不能推断无解或通过。
- **cancelled**：主动停止。UI 立即终止 Worker；引擎 API 也支持协作取消。
- **invalid-input**：非法配置、部分规格、初始样例与规格冲突。
- **internal-error**：内部异常；不当作反例。
- **worker-error**：Worker 加载、崩溃、协议、消息反序列化或超时故障。

## 资源边界

| 资源 | 硬上限 |
| --- | --- |
| 变量 / 常量 / 初始样例 | 2 / 8 / 64 |
| 域输入总数 | 4096（先计算笛卡尔积数量再枚举） |
| AST 搜索节点 / 规格节点 | 15 / 63 |
| 总候选尝试 / 总时间 | 5,000,000 / 30,000 ms |
| 每轮保留代表 / CEGIS 轮数 | 20,000 / 32 |
| 每轮候选验证输入 | 4096 |
| 轨迹 | 最近 128 条，记录省略数量 |
| 导入 JSON | 128 KiB UTF-8；文件读取前检查大小 |

总候选与时间预算跨轮累计，代表上限逐轮重置；累计统计不会当作每轮内存。每 2048 次候选尝试、层结束及候选/反例处向主线程发真实快照并让出 Worker 事件循环。时间预算是合作检查的墙钟上限，不是实时系统的精确截止保证；浏览器调度和快照传输可能增加耗时。UI 取消直接终止 Worker，不等待下一检查；Worker 长时间无响应单独报故障。轨迹为有界事件摘要，不保存每个被剪枝 AST；内存通过代表/样例/候选尺寸限制，不测量精确峰值 RSS。

目录：`src/core` 为算法；`src/synth.worker.ts` 为计算入口；`src/worker-client.ts` 管理生命周期；`src/App.tsx` 为中文界面；`tests/reference.ts` 为独立参考实现。

已知限制：指数搜索，只适合小型整数表达式；UI 不提供无限域证明、任意 JavaScript、浮点、递归和语句；导入不执行历史结果；仅 Chromium 自动验收，Firefox/WebKit、真实手机与用户 Windows 电脑人工试用未验证。后续可增加代价模型、更多纯运算符、独立 SMT 验证器或严格证明的增量等价更新；必须先保持当前错误语义和完整性保证。
