# MatchupLab v0.1 · 陌生对手策略学习实验室

面向学生、自学者和算法实验者的本地重复博弈平台：学习一个未知对手需要多少探索？对手改变后，原策略还能工作吗？训练表现能否迁移到新对手？不需要后端、数据库、账号、API Key 或付费服务；实验数据留在浏览器。它研究对抗决策与策略泛化，与本仓库的压缩、计算物理、约束求解、仓库分析及邮箱工具各自独立。

## 安装与运行（Windows / Linux）

需要 Node.js ≥22.12（建议 Node 22 LTS）和 npm。在 PowerShell、命令提示符或 shell 中：

```sh
cd projects/matchuplab
npm ci
npm run dev
```

打开终端显示的本地地址。无需 Python 或其他项目依赖。停止服务用 Ctrl+C。生产构建与预览：

```sh
npm run build
npm run preview
```

预览生产构建使用 HTTP 服务；不要直接双击 `dist/index.html`，模块 Worker 需要正确的同源资源加载。未部署网站。

## 两个同时行动、零和的重复博弈

矩阵的行是学习者动作，列是对手动作。每回合同时出招，学习者收益为表中数字，对手收益取相反数。正值胜、负值负、0 平；平局计入总回合与胜率分母。没有其他终局或随机结算。动作编号均为 0、1、2，越界及非整数动作会报错。

### 标准石头剪刀布

| 你 / 对手 | 石头 (0) | 布 (1) | 剪刀 (2) |
| --- | ---: | ---: | ---: |
| 石头 | 0 | -1 | 1 |
| 布 | 1 | 0 | -1 |
| 剪刀 | -1 | 1 | 0 |

范围 [-1,1]；均匀混合策略是零和纳什均衡，面对任意固定混合对手的期望收益为 0。学习可利用有偏对手，但不可能对独立均匀对手取得严格正的长期期望收益。

### 突击、防守、佯攻

| 你 / 对手 | 突击 (0) | 防守 (1) | 佯攻 (2) |
| --- | ---: | ---: | ---: |
| 突击 | 0 | -2 | 3 |
| 防守 | 2 | 0 | -1 |
| 佯攻 | -3 | 1 | 0 |

防守克制突击（2），佯攻克制防守（1），突击重创佯攻（3）。范围 [-3,3]；均匀策略不再是均衡，均衡概率为 (1/6,1/2,1/3)，价值为 0。收益幅度使动作风险不同。与石头剪刀布的原始收益不能直接公平排名。

## 五类可复现对手

| 策略 | 参数与行为 |
| --- | --- |
| 均匀随机 | 每个动作概率 1/3 |
| 固定动作 | `action`，始终出该动作 |
| 偏好动作 | `action` 的概率为 `bias` ∈ [0,1]；其余各为 (1−bias)/2 |
| 简单响应 | 第一回合均匀随机；此后针对学习者**上一回合**动作选择使其收益最小的动作，平手均匀。无法读取当前动作 |
| 非平稳切换 | 前 `switchRound=N` 回合出 `action`，从第 N+1 回合出 `nextAction`；N=0 表示立即切换 |

所有阶段都从对手第 1 回合和空历史开始；测试不是训练对手时钟的延续。例如 N=500 而测试仅 100 回合，测试不会发生切换。固定策略不消耗随机数，其余随机策略使用注入 PRNG。

## 统一 Agent 与算法

`act(random)`、`update(action,reward01)`、`policy()`、`state()`、`reset()` 构成统一接口。所有算法都只观察实际选择动作的收益，经验均值初始为 0，计数为 0；平手均匀抽取。更新前检查动作与奖励是否合法。`state()` 返回副本，`reset()` 重置全部计数、均值和权重。

所有学习更新使用 `x=(raw−game.min)/(game.max−game.min)` ∈ [0,1]，平局映射为 0.5。界面、统计和导出中的收益仍是原始矩阵单位。归一化让同一个环境内的算法获得一致输入，但不是跨环境难度校准。

| 算法 | 训练选取与更新 | 独立测试的冻结策略 |
| --- | --- | --- |
| 随机基线 | 均匀抽样，记录计数与均值但不用于决策 | 均匀概率 |
| ε-greedy | ε∈[0,1]；`p=(1−ε)·greedy(mean)+ε/K`，每次更新增量样本均值 | 经验均值最大的动作，平手均匀；关闭探索 |
| UCB1 | 先在零计数动作间均匀选择；全部访问后最大化 `mean+sqrt(2 ln(t)/n)`；t 为已有更新数 | 经验均值贪心，关闭置信奖励 |
| EXP3 | γ∈(0,1]；`p_i=(1−γ)q_i+γ/K`；选中动作的重要性估计 `x/p_i`，`log(w_i)+=γ·x/(K·p_i)` | `q_i=w_i/Σw`，关闭显式 γ 混合探索 |

EXP3 在 log 空间更新，每次减去最大 log 权重，通过稳定 softmax 计算概率；即使极小权重浮点下溢，训练混合概率仍至少 γ/K。学习率为 γ/K，不做额外温度或奖励裁剪。γ 是固定参数，用户应预先指定，不用测试结果调参。ε-greedy 与 UCB1 不强制先试每个动作的方式相同：只有 UCB1 保证先访问全部动作，ε=0 可陷于早期偶然结果。UCB1 的经典保证需要平稳随机收益；EXP3 的对抗设定要求收益有界、对手不能预知当前随机动作。这里的响应对手只依赖过去。冻结测试策略不等同于算法训练时的探索策略，也不继承训练期的理论遗憾界。

## 操作、模板与阶段隔离

1. 选择模板、环境、对手、算法、ε / γ、训练与测试回合、种子。默认批量比较全部四种算法，可取消勾选只跑所选算法。
2. **单局演示**创建一个种子的任务并推进一回合，保持暂停；**连续演示**以每批 8 步、约 60ms 间隔运行。暂停后可继续或单步。配置运行中锁定。
3. **批量比较**使用 base+i 的连续种子（uint32 回绕）。四种算法按相同配置、相同种子配对；每个算法拥有自己的状态与随机流。
4. 训练完成立即冻结策略，不向 Agent 提供测试收益。原对手独立测试使用新随机流、空历史与重置的对手时钟。
5. 开启迁移后，同一个冻结策略再对新对手测试。原对手测试和迁移测试使用相同的新随机流，便于配对比较；两者都与训练随机流隔离。响应对手会因算法历史不同而产生不同动作，不能假定各算法遭遇完全相同轨迹。
6. 切换观察阶段，查看均值/累计收益曲线、胜率、动作分布和按种子汇总。仅绘制首个种子，批量汇总覆盖所有完整运行。
7. 完整完成后可导出；取消或重置丢弃未完成结果，编辑配置或切换模板会清除旧结果，避免错误标注。

内置模板：固定对手学习（石头）、对手中途改变策略（第 501 回合石头→剪刀）、训练后迁移至新对手（训练石头，冻结测试石头和剪刀）。每个模板都支持四算法、多种子和两种导出。

## 可复现性、统计和导出

PRNG 为 Mulberry32。每阶段学习者与对手使用由 `(seed XOR imul(salt,0x9e3779b9)) >>> 0` 派生的独立状态；salt=1/2 对应训练 Agent/对手，3/4 对应评估 Agent/对手。相同配置、seed、算法和 v0.1 实现得到完全相同的输出，批次大小及暂停不改变序列。不使用 `Math.random()`。JSON 保留 schemaVersion、完整配置、算法列表与所有种子；按所列参数重新运行即可复现。

- 每阶段记录有效对局数 n、胜/平/负、胜率=胜/n、原始累计收益和平均收益、三个动作计数。
- 每次运行的 `metrics.sd` 是回合收益的样本标准差，用 Welford 算法计算，分母 n−1；它描述波动，不宣称对局相互独立。
- 汇总 `summary.sd` 是 S 个独立种子的**阶段均值**的样本标准差（分母 S−1）；另列种子均值的 min/max、种子数、对局总数、均值和平均胜率。所有种子阶段长度相同，均值与胜率采用种子等权平均。
- n=1 或 S=1 时 SD 显示 0，只表示没有可估计的样本方差，不能视为无风险。SD 不是置信区间，对手响应造成的相关性与阶段切换也不能靠增加单条轨迹回合数消除。
- JSON 包含阶段汇总、全体每种子运行汇总、冻结策略与抽样曲线。CSV 为每算法×种子×阶段一行，包含完整配置（含训练/迁移对手）、n、指标、回合 SD、动作计数及冻结策略；UTF-8 BOM、CRLF、RFC4180 双引号转义便于 Excel 使用。跨种子汇总在 JSON 的 summary 与页面提供，CSV 可据每种子行重算。
- 每阶段曲线最多 252 个点（首点、固定步长、末点），绘制当前阶段累计均值或累计收益；精确统计使用每一回合。最近对局仅保留 12 条，未导出完整逐回合轨迹。

## 预算、取消与模块

每阶段 1–20,000 回合，批量 1–32 种子；`(训练回合+测试回合×评估阶段数)×算法数×种子数 ≤ 2,000,000`，启动前及 Worker 内均校验。每个 Worker 批次最多 512 回合，批次间让出事件循环；累计执行批次的计算时间限制为 30 秒（不计暂停和定时器等待）。取消消息在批次边界处理；重置直接终止当前 Worker，迟到消息用实例检查隔离。异常以页面错误显示且禁止导出部分结果。后台标签节流可延长实际耗时。

```text
src/core/games.ts       规则、收益、奖励映射
src/core/random.ts      注入式伪随机与抽样
src/core/agents.ts      Agent 接口及四种算法
src/core/opponents.ts   五类只读历史对手
src/core/config.ts      模板、参数与预算校验
src/core/simulation.ts  分阶段引擎与增量批量任务
src/core/statistics.ts  在线统计及跨种子汇总
src/core/export.ts      CSV / JSON
src/worker.ts           调度、暂停、取消与计算预算
src/ui/                配置、SVG 图表及解释
```

## 已知限制与后续

当前仅支持三个离散动作的两个矩阵环境、固定超参数及有限时域实验，无参数自动搜索、神经网络、遗憾最小化求解器或跨对手总体泛化保证。累计样本均值没有遗忘机制，非平稳对手可显著降低 UCB / ε-greedy 的适应能力。冻结权重形成的策略可能被新对手利用；均衡策略也不必在短期随机样本中胜出。少量种子和按测试结果挑选参数会导致误判，建议预先设定研究问题及参数并增加独立种子。图表只展示首个种子，不能代替跨种子统计。

本地 Linux Chromium 验证不代表真实 Windows 桌面或所有浏览器人工验收；Windows 自动验证由远程 CI 单独记录。后续可按需求增加滑动窗口/折扣算法、配对差异统计与自定义矩阵导入；不扩展为线上对战服务。
